# 前端组件拆分设计

## 背景

听书功能加入后，`App.tsx` 同时承担应用模式路由、运行时播放器创建、白噪音调音台、ASMR 调音台和听书入口接线。单文件职责开始膨胀，后续继续增加模式或播放能力时，入口文件会变成改动冲突点。

## 目标

- 保持现有白噪音、ASMR 和听书行为不变。
- 让 `App.tsx` 只保留根组件转发，不承载应用模式、播放依赖创建或业务 JSX。
- 让 `AppWorkspace` 负责应用工作区编排、运行时依赖创建和模式可见性切换。
- 把模式切换组件独立出来，避免听书视图反向暴露应用导航。
- 把声音调音台视图移动到 `features/mixer`，让调音台自己的状态、配置和 UI 留在同一能力域。
- 避免为了拆分而新增复杂状态容器、全局 context 或抽象层。

## 非目标

- 不重做视觉设计。
- 不调整播放器协议 `PlayerPort`。
- 不调整听书 `TtsEnginePort`。
- 不改变声音、预设、自定义音频和听书的用户可见交互。
- 不引入新的前端依赖。

## 模块边界

### 应用模式

新增 `features/appMode`：

- `appModeTypes.ts`：定义 `AppMode`。
- `AppModeSwitcher.tsx`：渲染“声音 / 听书”切换。

这个模块只关心模式枚举和切换事件，不依赖播放器、声音库或听书引擎。

### 声音调音台

新增 `features/mixer`：

- `soundLibraryModes.ts`：保存声音库来源筛选配置。
- `SoundMixerView.tsx`：承载调音台 UI、预设区、自定义音频入口和声音列表。
- `MixerHeader.tsx`、`ActiveMixPanel.tsx`、`MixPlanPanel.tsx`、`CustomAudioPanel.tsx`、`SoundGrid.tsx`：拆分调音台局部 UI，让 `SoundMixerView.tsx` 只负责状态编排。

调音台仍依赖既有的 `useSoundMixer`、`useCustomSounds`、声音目录和预设目录。该模块不依赖听书能力。

### 听书视图

听书视图保留 `AudiobookView.tsx` 作为状态编排层，继续持有书名、书稿、导入状态和 `useAudiobookPlayer`。局部 UI 拆分到同目录组件：

- `AudiobookStatusPanel.tsx`：展示当前状态和片段进度。
- `AudiobookImportPanel.tsx`：书名输入和文本文件导入。
- `AudiobookSettingsPanel.tsx`：音色和语速设置。
- `AudiobookTransport.tsx`：上一段、播放、下一段和停止。
- `AudiobookReader.tsx`：文本编辑区和分段列表。

这些组件只接收明确 props，不直接读取 TTS 引擎或播放器实现，避免 UI 分区和播放状态逻辑耦合。

### 应用工作区

新增 `features/appMode/AppWorkspace.tsx`：

- 创建或接收 `PlayerPort`。
- 创建或接收 `TtsEnginePort`。
- 维护当前 `AppMode`。
- 根据模式控制 `SoundMixerView` 和 `AudiobookView` 的可见性。
- 声音调音台常驻挂载；听书在用户首次进入后挂载并保持挂载。
- 模式切换不停止 `PlayerPort` 或 `TtsEnginePort`，两类声音可以同时播放。

`App.tsx` 不接收业务 props，只渲染 `AppWorkspace`。测试注入用的 `player` 和 `ttsEngine` 由 `AppWorkspace` 接收，入口文件不导入业务 CSS，不再承载业务编排。

## React 约束

- 不在组件内部定义新的组件，避免每次 render 生成新的组件类型。
- 静态模式配置放在模块级常量。
- 子视图用明确的 props 传入依赖，不增加全局 context。
- 保留已有 `useMemo` 和 `useCallback` 只用于真实依赖稳定或派生集合，不为了形式包裹简单表达式。
- 派生列表摘要时避免在 render 中多次遍历同一声音集合；使用一次 `reduce` 或 `useMemo` 固定依赖。
- 不为普通按钮新增 boolean prop 变体；当 UI 区域继续增长时，优先拆显式组件，而不是给同一个组件叠加模式分支。

## React skill 复核问题

- `AudiobookView.tsx` 仍然超过 300 行，并同时承载导入、设置、播放控制和阅读区。对照 `architecture-avoid-boolean-props` 和 `patterns-explicit-variants`，应拆成明确的局部组件，让主视图只保留状态编排。
- `SoundMixerView.tsx` 中 `activeSummary` 通过 `filter` 再 `map` 派生，且每次 render 都执行。对照 `js-combine-iterations` 和 `rerender-dependencies`，应把摘要派生收敛为一次 `useMemo`。
- 暂不为所有子组件加 `memo`。当前交互状态频繁变化且组件 props 多数会随播放状态更新，盲目 `memo` 容易增加比较成本和维护成本；后续若声音卡片数量继续增长，再以 profiler 结果决定。

## CSS 拆分策略

- `src/styles/global.css` 保留全局设计 token、reset、基础排版、页面背景和根节点规则。
- `src/styles/ui.css` 保留跨声音调音台和听书复用的玻璃面板、错误提示、标题、播放按钮和文件导入按钮等共享 UI 规则。
- `src/features/appMode/AppWorkspace.css` 只包含应用工作区壳子、模式面板和播放器加载态样式。
- `src/features/appMode/AppModeSwitcher.css` 只包含应用模式切换样式。
- `src/features/mixer/SoundMixerView.css` 包含白噪音和 ASMR 调音台布局、预设、声音卡片、自定义音频面板和调音台响应式规则。
- `src/features/audiobook/AudiobookView.css` 包含听书布局、导入、设置、播放控制、阅读区和听书响应式规则。
- 删除 `src/App.css`，避免入口文件继续成为业务样式堆积点。
- 继续保留现有 className，不在本轮引入 CSS Modules，避免同时修改结构、样式作用域和测试选择器。

## 验收标准

- `App.tsx` 行数明显下降，并且不再包含调音台 JSX、听书 JSX、模式状态或运行时依赖创建。
- `App.css` 删除，新增业务样式不能再回到应用入口文件。
- 原有应用集成测试迁移到 `AppWorkspace` 后继续通过。
- 白噪音、ASMR、听书入口和听书播放相关测试继续通过。
- 完整门禁通过：

```bash
pnpm run check
git diff --check
```
