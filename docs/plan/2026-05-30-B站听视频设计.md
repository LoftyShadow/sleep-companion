# B站听视频设计

## 目标

在现有“声音 / 听书”之外新增“听视频”模式。第一版支持用户粘贴 B 站视频、番剧或直播间链接，在应用内通过 B 站官方播放器播放，满足临时听视频声音的使用场景。

## 第一版范围

第一版包含：

- 支持粘贴 `bilibili.com`、`www.bilibili.com`、`m.bilibili.com` 和 `b23.tv` 链接。
- 支持解析普通视频 `BV` 号链接。
- 支持解析普通视频 `av` 号链接。
- 支持解析番剧或影视 `ep` 链接。
- 支持解析 B 站直播间链接，例如 `https://live.bilibili.com/23058` 和 `https://live.bilibili.com/blanc/23058`。
- 支持用户直接粘贴 `BV`、`av` 或 `ep` 标识。
- 普通视频和番剧使用 `https://player.bilibili.com/player.html` 官方外链播放器嵌入播放。
- 直播间使用 B 站直播官方活动播放器 `https://www.bilibili.com/blackboard/live/live-activity-player.html?cid=房间号` 嵌入播放。
- 右侧以音频收听面板为主视觉，展示当前来源、标题、封面和连接状态；官方播放器作为播放源保留在面板内。播放源载入后默认展开，方便用户直接使用 B 站播放器自身的播放、暂停、音量、清晰度和跳转能力；用户只想听声音时可以手动收起画面。
- 载入普通视频、番剧或直播间后，通过 Tauri 后端命令只读获取 B 站标题和封面元信息，用于收听面板展示。
- 收听面板保留播放/暂停入口和音量区域。直播来源通过官方 `postMessage` 控制播放暂停并同步音量；普通视频外链没有公开外部控制接口，播放/暂停入口只负责展开官方播放器，不通过卸载 iframe 暂停播放，用户直接在默认展开的 B 站官方播放器内控制播放暂停、清晰度、音量和跳转。
- 普通视频外链没有公开外部音量接口，收听面板保留音量区域但禁用外层音量条，避免误导用户以为外层滑条可以控制跨域 iframe 音量。
- 点击“载入”后通过官方播放器参数尝试自动播放；是否真正自动出声由浏览器、WebView 和 B 站播放器策略决定。
- 链接输入区提供“粘贴”按钮，读取系统剪贴板文本并填入输入框；读取失败时允许用户手动粘贴。
- 显示当前解析出的 B 站标识，方便确认链接是否识别正确。

第一版不包含：

- 不抓取 B 站真实音视频流地址；标题和封面元信息不视为媒体流抓取。
- 不下载、缓存、转码或离线保存视频和音频。
- 不把 B 站视频转为本地音频源。
- 不隐藏官方播放器后只播放音频；收听面板只是外观弱化，不替代官方播放器。
- 不绕过 B 站登录、会员、地区、版权、广告或其它播放限制。
- 不做播放列表、收藏、历史记录或账号体系。
- 不做非 B 站平台。

## 架构

新增 `videoListening` 功能域：

```text
B 站链接输入
  -> parseBilibiliInput
  -> BilibiliSourceKind
  -> getBilibiliSourceStrategy
  -> iframe 官方播放器或直播播放器
```

播放引用解析器只做字符串解析，不请求网络。解析成功后输出明确的引用类型：

```ts
enum BilibiliSourceKind {
  Video = "video",
  Live = "live",
}

type BilibiliReference =
  | { kind: "bvid"; value: string }
  | { kind: "aid"; value: string }
  | { kind: "ep"; value: string }
  | { kind: "live"; value: string };
```

播放器 URL 只拼接官方播放器支持的参数：

- `bvid` 用于 BV 号。
- `aid` 用于 av 号。
- `episodeId` 用于番剧或影视 ep 号。
- `autoplay=1`，在用户点击载入后尝试自动播放。
- `cid` 用于直播房间号。
- `mute=0`，直播播放器默认不主动静音；最终是否有声仍受浏览器和 B 站播放器策略限制。

视频和直播使用枚举区分策略。策略工厂只负责把解析出的引用转换为可嵌入 source；UI 不直接拼播放器 URL。

标题和封面通过独立的 Tauri 后端命令获取：

- 普通视频 `BV` 和 `av` 只读取 `title` 与 `pic`。
- 番剧或影视 `ep` 只读取当前分集标题与封面，缺失时回退到季标题与季封面。
- 直播间只读取直播标题与 `user_cover`，缺失时回退到关键帧图。
- 后端命令只接受已经解析出的 `bvid`、`aid`、`ep` 或直播房间号，不接受任意 URL，避免成为通用网络代理。
- 元信息获取失败不阻断官方播放器载入，界面显示“元信息暂不可用”并保留解析出的 B 站标识。

## 合规边界

本功能只作为 B 站官方播放器的嵌入入口。应用不拥有、复制、下载或重新分发 B 站内容，不绕过 B 站播放器本身的限制。

如果 B 站官方播放器拒绝某个视频或直播、需要登录、地区不可用、会员不可用、直播间不可展示或版权不可用，应用只展示播放器自身状态，不尝试降级到抓流或第三方解析。

## UI 设计

听视频模式包含：

- 左侧控制区：模式标题、链接输入、载入按钮、当前视频状态。
- 右侧收听区：音乐播放器风格的当前来源卡片、标题、封面、连接状态、播放/暂停入口、音量区域和默认展开且可收起的官方 iframe 播放源。直播来源的外层控件可同步到直播播放器；普通视频来源的播放、暂停、音量、清晰度和跳转由官方播放器内部控件完成。

界面不加入长篇说明文字，只保留必要按钮、输入状态和错误提示。输入框支持粘贴完整链接或短标识；用户可以点“粘贴”从剪贴板填入链接，也可以手动输入。用户点击“载入”后更新播放器并尝试自动播放。

## 错误处理

- 空输入显示“请输入 B 站视频或直播链接”。
- 无法识别的输入显示“暂时只支持 B 站 BV、av、ep 和直播间链接”。
- 非 B 站域名链接显示同样的不支持提示。
- 当前环境不能读取剪贴板或读取失败时，显示明确错误并保留手动输入能力。
- 标题或封面元信息获取失败时，显示“元信息暂不可用”，继续使用解析出的 B 站标识和官方播放器。
- iframe 加载失败不做自定义抓流兜底，只保留官方播放器可见状态。

## 验收标准

- 可以从 `https://www.bilibili.com/video/BV...` 解析出 `bvid` 并生成官方播放器 URL。
- 可以从 `https://www.bilibili.com/video/av...` 解析出 `aid` 并生成官方播放器 URL。
- 可以从 `https://www.bilibili.com/bangumi/play/ep...` 解析出 `episodeId` 并生成官方播放器 URL。
- 可以从 `https://live.bilibili.com/...` 解析出直播房间号并生成官方直播播放器 URL。
- 生成的官方播放器 URL 使用 `autoplay=1`。
- 生成的官方直播播放器 URL 使用 `cid=房间号`。
- 普通视频来源载入后默认展开官方播放器，外层不会用暂停按钮卸载 iframe。
- 直播来源可以通过外层收听音量条发送 `changeVolume` 消息。
- 普通视频来源会保留播放/暂停入口和音量区域；点击播放/暂停入口只展开官方播放器，不卸载 iframe；外层音量条禁用，用户在官方播放器内调整音量。
- 普通视频、番剧和直播间载入后，收听面板可以展示获取到的标题和封面。
- 元信息获取失败时，官方播放器仍然载入，收听面板回退展示解析出的 B 站标识。
- 粘贴按钮可以把剪贴板文本填入视频或直播链接输入框。
- 不能识别非 B 站链接。
- 顶层应用显示“声音 / 听书 / 听视频”三个模式。
- Android 移动端顶层模式导航固定在屏幕底部，用户滚动到长页面中段后仍可直接切换“声音 / 听书 / 听视频”。
- 切换到听视频不会停止声音调音台或听书。
- 必须通过：

```bash
pnpm run check
```
