# Web 桌面 UI/UX 重设计

## 背景

当前 Web、Linux 和 Windows 端共用同一套 React 前端。桌面端只额外显示自定义窗口栏和内置滚动容器，因此主界面的 UI/UX 可以共用一套重设计。Android 真机布局和原生播放链路不纳入本次改动。

## 目标

- 改善主界面的信息架构，让用户打开后先看到当前场景、主操作和推荐入口。
- 把声音页从“控制面板堆叠”改成“场景构建流程”：场景总览、播放控制、预设推荐、声音细调。
- 把 Web、Linux、Windows 的顶部导航和全局定时整合成工作台级控制区。
- 保留现有播放、导入、定时停止、模式切换和窗口控制行为。
- 不引入新的 UI 框架，不改变组件职责边界。
- 移动窄屏保持可用，不针对 Android 原生体验做专项改造。

## 非目标

- 不新增声音、预设或业务能力。
- 不调整 Android 原生音频桥接、APK 打包或移动端安装流程。
- 不重写组件结构，不迁移到 CSS Modules 或 Tailwind utility 写法。
- 不引入动效库、图标库或远程图片资源。

## 交互设计方向

整体从“功能卡片集合”调整为“桌面工作台”：

- 工作台顶部：显示产品上下文、应用模式切换和全局定时停止，减少顶部散落感。
- 声音页首屏：左侧是当前模式和使用引导，右侧是当前播放状态和主播放按钮。
- 预设区：作为“快速开始”入口，位于声音库前，降低用户从零调音的成本。
- 声音库：作为第二步细调区域，保留单音播放、音量和自定义音频。
- 听书页：改成“书稿概览 / 主朗读 / 导入设置 / 内容跟读”的两段式工作流，播放状态和主操作前置到首屏。
- 听视频页：改成“链接载入 / 当前收听 / 官方播放源”的两段式工作流，外层播放控制前置，官方 iframe 下沉为可展开来源区。

## 组件边界

- `AppWorkspace`：增加工作台级顶部控制区，继续负责模式切换、定时停止和滚动。
- `SoundMixerView`：重排声音页信息架构，负责场景构建流程的区块编排。
- `MixerHeader`：展示模式、引导和当前可用资源统计。
- `ActiveMixPanel`：展示当前混音、播放状态和主播放操作。
- `MixPlanPanel`：作为推荐混音和我的混音区域。
- `SoundGrid`：作为声音细调区域。
- `AudiobookView`：重排听书页信息架构，继续只编排既有导入、设置、朗读控制和阅读器组件。
- `VideoListeningView`：重排听视频页信息架构，继续只编排既有链接载入、收听控制和官方播放源。
- `styles/global.css` 和 `styles/ui.css`：只放全局 token、基础背景和共享 UI 原子样式。

## 验收标准

- Web、Linux、Windows 共享同一套工作台级导航和声音页场景构建流程。
- 声音页首屏能清楚区分“当前场景 / 主播放 / 快速预设 / 声音细调”。
- 听书页首屏能清楚区分“书稿概览 / 当前朗读”，导入设置和朗读内容作为下方工作区。
- 听视频页首屏能清楚区分“链接载入 / 当前收听”，官方播放源作为下方可展开区域。
- 窄屏下仍为单列布局，按钮文字不溢出，主要内容不互相遮挡。
- 不改变现有测试可观察行为。
- `pnpm run check` 或本机可用等价命令通过。
- 如本机可启动预览，应至少用浏览器检查主界面首屏是否非空且布局正常。
