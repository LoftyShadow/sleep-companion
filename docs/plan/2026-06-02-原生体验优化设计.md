# 原生体验优化设计

## 背景

本项目当前使用 Tauri 2、React 19 和 Android Kotlin 原生桥接实现跨平台睡眠陪伴体验。现有实现已经能覆盖 Web、桌面端和 Android 前台播放，但从原生体验审查结果看，仍有几类需要收敛的问题：

- Android `MediaPlayer` 和 `TextToSpeech` 没有绑定 Tauri Android 插件生命周期。
- 音量滑块拖动时会把每一次 `input` 变化都发送到 Android 原生播放器，容易形成跨 WebView、Tauri、Rust、Kotlin 边界的热路径。
- 桌面端为了统一视觉使用自绘标题栏和 Web 风格交互细节，部分行为和平台习惯不一致。
- Tauri WebView 生产配置未设置明确 CSP，安全边界偏宽。

本设计不推翻 Tauri 架构，而是在现有架构内按“让平台做平台擅长的事、跨边界调用要有意图”的原则收紧实现。

## 目标

- Android 原生音频和 Android 系统 TTS 在 Activity 停止或销毁时可靠释放。
- 保持第一版 Android 行为边界：只承诺前台真机播放，不实现后台或锁屏播放。
- 音量调整在 UI 上保持即时反馈，同时减少拖动过程中的高频 IPC。
- 桌面端减少明显 Web 风格信号，包括全局手型光标和网页式平滑滚动。
- 在不破坏现有自绘标题栏设计的前提下，记录更原生标题栏方案的取舍，并做低风险细节优化。
- 为 Tauri WebView 设置生产可用的基础 CSP。

## 非目标

- 不把 Tauri 改为纯 Swift、C#、WPF、WinUI 或 Electron。
- 不实现 Android 后台播放、锁屏控制、通知栏播放控制或前台服务。
- 不把 Android `MediaPlayer` 替换为 Media3/ExoPlayer。
- 不重做桌面标题栏视觉体系。
- 不新增系统托盘、菜单栏、多窗口、全局快捷键或自动更新能力。
- 不引入新的前端样式框架。

## 架构原则

### 平台生命周期优先

Android 原生播放器和 TTS 引擎属于平台资源，不能只依赖 React 组件卸载释放。Tauri Android 插件提供 `onStop()` 和 `onDestroy(...)` 生命周期入口，原生资源释放应在插件侧兜底。

第一版不支持 Android 后台播放，因此：

- `onStop()` 停止正在播放的内置音频。
- `onStop()` 停止正在朗读的 Android TTS。
- `onDestroy(...)` 释放全部 `MediaPlayer`。
- `onDestroy(...)` 调用 `TextToSpeech.shutdown()`。

未来如果要支持后台播放，应先新增前台服务或 Media3/ExoPlayer 设计，再调整这些生命周期策略。

### 跨边界调用节流

音量拖动属于高频交互。UI 层应立即更新本地状态，保证滑块和值显示没有延迟；原生播放器调用可以按声音 ID 合并和节流。

设计约束：

- `setSoundVolume(soundId, volume)` 继续保持现有对外接口。
- 本地 `volumes` 状态同步更新。
- 仅对底层 `PlayerPort.setVolume` 做短时间合并。
- 同一个 `soundId` 在同一帧或极短窗口内只提交最后一次音量。
- 播放、暂停、停止和预设切换仍立即调用播放器，不走音量节流队列。
- 播放或暂停同一个声音前取消该声音的待提交音量；播放时直接把最新音量传给 `play(sound, volume)`。
- `stopAll()` 和预设切换前要取消待提交音量，避免停止后又补发旧音量。
- 手动调整音量时立即清除 `activePresetId`；底层延迟提交完成后不得再改预设状态，避免慢速 `setVolume` 回调覆盖后续新应用的预设。
- `setSoundVolume(...)` 的 `Promise` 完成只表示该次用户输入已被处理；如果后续停止、预设切换或组件卸载取消了待提交音量，不代表底层 `PlayerPort.setVolume` 一定已经执行。

### 桌面端低风险原生感优化

当前已经有桌面窗口栏美化设计，并明确使用无系统装饰窗口。本次不直接回退该方案，而是先处理不改变布局的细节：

- 桌面 Tauri 环境下按钮默认光标恢复为系统默认光标。
- 浏览器 Web 预览保留手型光标，避免影响 Web 用户预期。
- 听书段落列表移除常驻 `scroll-behavior: smooth`，让系统滚动行为主导。
- 保留后续“平台化标题栏”的方向：macOS 使用左侧交通灯习惯，Windows 使用右侧 caption buttons，Linux 兼容桌面环境差异。

### CSP 收紧

Tauri WebView 运行的是本地前端，但仍应限制资源来源。基础策略应允许：

- 本地脚本、样式、图片、字体、音频。
- Tauri 自身协议和 Android 资源访问所需来源。
- B 站元数据或嵌入相关必要网络来源。
- 开发环境由 Tauri/Vite 配置处理；生产配置优先安全。

如果后续功能需要新增远程域名，必须显式加入 CSP，而不是恢复 `null`。

## 风险和取舍

- Android 进入后台后停止播放是有意行为，符合第一版“前台真机播放”边界；用户如果期待后台播放，需要后续单独设计。
- 音量 IPC 节流会让底层播放器收到音量变化稍晚于 UI，但最终值必须准确。
- CSP 收紧可能暴露当前资源来源遗漏，验证时需要关注 Web、Tauri 桌面和 B 站听视频入口。
- 自绘标题栏仍不是最原生方案，本次只做低风险改良，不解决所有平台窗口语义差异。

## 验收标准

- Android 音频插件在 `onStop()` 和 `onDestroy(...)` 时停止并释放播放器。
- Android TTS 插件在 `onStop()` 时停止朗读，在 `onDestroy(...)` 时关闭引擎。
- 音量拖动连续触发时，UI 状态立即变化，底层 `PlayerPort.setVolume` 按声音 ID 合并提交。
- `stopAll()`、预设切换和组件销毁不会补发过期音量。
- 桌面 Tauri 环境按钮不再统一使用手型光标。
- 听书段落列表不再强制网页式平滑滚动。
- `tauri.conf.json` 不再使用 `csp: null`。
- 本地质量门禁通过：

```bash
pnpm run check
```
