# 听书书架与进度恢复设计

## 背景

当前听书入口只维护当前会话中的一本书。用户导入文本或 EPUB 后可以朗读、切章节和切片段，但书籍内容、封面和阅读进度没有形成可恢复的本地书库。用户希望像书架一样管理多本书，并在下次打开应用后继续从上次位置收听。

本设计参考 `/home/niemingzhi/RustroverProjects/readest` 的存储分层方式：业务层通过 `FileSystem` 抽象读写书库和书籍配置，具体存储实现由运行环境决定。第一版不引入完整原生文件系统、SQLite、云同步、注释、高亮或 Foliate 阅读器，只在当前项目内实现 IndexedDB 文件系统后端。

## 目标

- 新增 `FileSystem` 抽象，第一版使用 IndexedDB 实现。
- 听书支持本地多本书书架。
- 导入 TXT、Markdown、EPUB 后写入本地书库。
- 处理书名：保留 EPUB 元数据标题，纯文本使用文件名，可在 UI 中重命名当前书。
- 处理封面：优先提取 EPUB manifest 中的封面图片；没有封面时生成稳定的文字书封。
- 每本书独立保存片段级进度，下次打开可继续播放。
- 保留现有系统 TTS 播放、章节导航、浮动播放控制和全局停止能力。

## 非目标

- 不做跨设备同步。
- 不做书籍分组、搜索、排序配置和批量管理。
- 不做 EPUB CFI 精确定位、注释、高亮和全文阅读器。
- 不迁移到 Tauri 原生文件系统或 SQLite。接口设计允许后续替换实现，但本次只接入 IndexedDB。
- 不处理 DRM 或加密 EPUB。

## 数据模型

书库列表只保存轻量摘要：

```ts
interface AudiobookLibraryItem {
  id: AudiobookBookId;
  title: string;
  author?: string;
  format: "plain-text" | "epub";
  fileName: string;
  createdAt: number;
  updatedAt: number;
  lastOpenedAt: number;
  segmentCount: number;
  chapterCount: number;
  progress: AudiobookProgress;
  cover: AudiobookCover;
}
```

书籍正文单独保存为 JSON：

```text
audiobooks/library.json
audiobooks/books/<book-token>/book.json
audiobooks/books/<book-token>/cover
```

进度使用片段级定位：

```ts
interface AudiobookProgress {
  segmentIndex: number;
  segmentId: string | null;
  chapterTitle?: string;
  sourceHref?: string;
  percent: number;
  updatedAt: number;
}
```

当前项目的听书播放以 `AudiobookSegment` 为单位，片段级定位比 EPUB CFI 更符合第一版范围。后续如果接入完整阅读器，可以在不破坏 `FileSystem` 抽象的前提下增加 CFI 字段。

## 架构

```text
AudiobookView
  -> useAudiobookLibrary
     -> audiobookLibraryStore
        -> FileSystemPort
           -> IndexedDbFileSystem
  -> useAudiobookPlayer
     -> TtsEnginePort
```

组件边界：

- `AudiobookView`：页面编排、全局停止、浮动播放控制对接。
- `AudiobookLibraryPanel`：书架列表、导入、打开、删除。
- `AudiobookImportPanel`：当前书名编辑和文件导入。
- `AudiobookReader`：章节与片段阅读区域。
- `useAudiobookLibrary`：书库初始化、导入、打开、删除、重命名、进度保存。
- `audiobookLibraryStore`：纯存储服务，负责路径、JSON 读写、封面二进制读写。
- `FileSystemPort`：文件读写抽象。
- `indexedDbFileSystem`：IndexedDB 文件系统实现。

## 封面策略

EPUB 封面提取顺序：

1. 读取 OPF manifest 中 `properties` 包含 `cover-image` 的资源。
2. 读取 EPUB 2 常见的 `<meta name="cover" content="...">` 指向的资源。
3. 如果命中图片资源，写入 `audiobooks/books/<book-token>/cover`。
4. 如果没有命中，使用生成书封。

生成书封不写文件，只保存主题色和标题首字：

```ts
{ kind: "generated", accent: "#2d7d82", initials: "三" }
```

## 进度保存

`useAudiobookPlayer` 增加：

- `initialSegmentIndex`：打开书时恢复到上次片段。
- `resetKey`：只在切换书时重置播放器，不因进度状态刷新打断播放。
- `onProgressChange`：播放或跳转到新片段时通知书库保存进度。

进度更新频率是片段级，而不是播放秒级。第一版可以每次片段变化时写入书库摘要；如果后续改成滚动阅读进度，再增加防抖。

## 风险

- IndexedDB 受浏览器或 WebView 存储配额限制，大书或大量书可能保存失败。
- 用户清理浏览器数据或应用 WebView 数据会删除书库。
- 当前 EPUB 文本提取是轻量实现，无法覆盖所有复杂 EPUB 排版和封面写法。
- 片段算法变化可能导致旧进度定位不完全精确；通过 `segmentId`、`sourceHref` 和 `segmentIndex` 组合降低风险。

## 验收标准

- 可以导入 TXT、Markdown、EPUB 到书架。
- 书架展示多本书、书名、格式、片段数、进度和封面。
- EPUB 测试夹具可提取封面时保存图片封面；没有封面时显示生成书封。
- 打开一本书后能从保存的片段继续播放。
- A 书和 B 书的进度互不覆盖。
- 重启页面后书架和进度仍可恢复。
- 删除当前书会停止当前听书并从书架移除。
- `pnpm run check` 通过。
