# B站UP主列表与最新视频刷新设计

## 目标

在已有“听视频”模式中增加 B 站 UP 主列表。用户可以把公开 UP 主保存到本地列表，选择某个 UP 主后刷新其最新公开视频，并点击视频直接接入现有 B 站官方播放器播放。

## 第一版范围

第一版包含：

- 用户可以输入 B 站 UP 主主页链接或 `mid` 添加 UP 主。
- 用户保存的 UP 主列表只保存在本地，不要求登录 B 站账号。
- 保存内容包含 `mid`、名称、头像、添加时间、更新时间和最后刷新时间。
- 用户可以删除已保存 UP 主。
- 用户点击某个 UP 主后，可以刷新该 UP 主最新公开视频列表。
- 最新视频列表展示标题、封面、发布时间、时长、播放量和视频标识。
- 用户点击视频后，复用现有 `createBilibiliPlaybackSource` 与官方 iframe 播放源载入视频。
- 公开视频列表刷新失败时，只显示错误提示，不影响手动粘贴链接播放。
- 已刷新的视频列表缓存在当前页面状态中；UP 主列表持久化保存。

第一版不包含：

- 不设计 B 站用户登录、授权、扫码或用户 cookie 导入。
- 不读取用户自己的关注列表、收藏夹、稍后再看、历史记录或推荐。
- 不抓取真实音视频流地址。
- 不下载、缓存、转码或离线保存 B 站媒体。
- 不绕过 B 站登录、会员、版权、地区或风控限制。
- 不做云同步、分组、批量导入、自动定时刷新和已看标记。

## 数据来源与合规边界

本功能使用 B 站网页侧公开视频信息接口获取公开视频列表。实现优先在单次请求链路中建立匿名空间访问会话，获取 B 站下发的匿名 cookie 和 WBI key，再请求 WBI 签名后的公开动态接口分页读取视频动态。动态分页最多扫描 10 页，收集到 12 条公开视频后立即停止；如果动态接口失败，最后才尝试 WBI 投稿接口兜底。上述接口不是本项目拥有的稳定契约，可能因为 B 站风控、接口变更、地区网络、登录策略或 WBI 签名规则变化而失败。

实现必须遵守以下边界：

- 后端命令只接受 UP 主 `mid`，不接受任意 URL，避免成为通用网络代理。
- 前端只保存用户主动添加的公开 UP 主信息。
- 不保存 B 站用户凭证；匿名 cookie 只作为单次请求上下文使用。
- 视频播放继续通过 B 站官方外链播放器，不做媒体流解析。
- 外部接口失败时保留明确错误，不伪造刷新成功。
- 手动视频链接播放与 UP 主列表刷新解耦，外部投稿接口失败不影响已有听视频能力。

## 架构

新增三个局部能力，全部放在 `videoListening` 功能域内：

```text
UP 主输入
  -> parseBilibiliCreatorInput
  -> fetch_bilibili_creator_videos
  -> 本地保存 creator
  -> 点击 creator 刷新公开视频
  -> 点击 video 载入官方播放器
```

前端模块：

- `bilibiliCreator.ts`：定义 UP 主、视频、输入解析、后端 loader 和响应校验。
- `bilibiliCreatorStore.ts`：基于 `FileSystemPort` 保存本地 UP 主列表。
- `useBilibiliCreators.ts`：封装列表加载、添加、删除、选择、刷新和错误状态。
- `BilibiliCreatorPanel.tsx`：渲染 UP 主保存区和最新视频列表。
- `VideoListeningView.tsx`：保留现有链接播放能力，接入 `BilibiliCreatorPanel` 的视频选择事件。

后端模块：

- 复用 `bilibili_metadata.rs` 中的网络请求和 JSON 解析方向。
- 新增 `fetch_bilibili_creator_videos` Tauri 命令。
- 命令入参包含 `mid`、`limit` 和可选浏览器指纹参数；`limit` 最大为 12；命令仍只允许访问指定 UP 主公开视频信息，不接受任意 URL。
- 命令优先建立匿名空间访问会话，获取 WBI 图片 key，计算 WBI 签名后分页请求公开动态接口。
- 动态分页最多扫描 10 页，按 `BV` 去重，收集到 `limit` 条或没有下一页时停止。
- 动态接口仍失败时，命令请求 WBI 投稿接口作为兜底。
- 只返回 UI 所需的轻量字段，不返回完整接口响应。
- Web 开发和预览环境没有 Tauri `invoke`，通过 Vite 本地 API 代理 `/api/bilibili/creator-videos` 走同一套 WBI 签名动态分页优先、WBI 投稿兜底策略；生产 Web 需要提供等价后端 API 或配置 `VITE_BILIBILI_API_BASE_URL`。

## Component Map

```text

BilibiliCreatorPanel：UP 主添加、列表选择、刷新按钮、视频列表、删除按钮。
useBilibiliCreators：本地列表状态、刷新状态、当前选择、异步动作。

```

## 错误处理

- 空输入显示“请输入 UP 主主页链接或 mid”。
- 非 B 站空间链接或无法解析的输入显示“请输入 B 站 UP 主主页链接或数字 mid”。
- 重复添加时选择已有 UP 主，并提示已在列表中。
- 本地保存不可用时提示“本地 UP 主列表不可用”，不影响手动链接播放。
- 动态接口、投稿接口返回失败、风控或网络错误时显示后端返回的错误摘要。
- UP 主没有公开视频时显示空状态。

## 破坏性更新说明

本功能没有破坏性更新：

- 不删除现有听视频能力。
- 不改变现有链接解析和官方播放器 URL 生成方式。
- 不要求迁移旧用户数据。
- 不改变声音、听书和全局播放控制行为。

## 验收标准

- 可以从 `https://space.bilibili.com/123456` 解析出 `mid=123456`。
- 可以直接输入数字 `mid` 添加 UP 主。
- 添加 UP 主后，本地列表重新加载仍保留。
- 重复添加同一 `mid` 不生成重复列表项。
- 删除 UP 主后，本地列表不再显示该项。
- 选择 UP 主并刷新后，最新视频列表展示公开视频信息。
- 请求 `limit=12` 时最多展示 12 条公开视频；如果第一页视频不足，会继续分页查询直到达到上限、动态没有下一页或扫描满 10 页。
- 点击视频后，现有收听面板载入对应 `BV` 官方播放器。
- 公开视频列表刷新失败时，手动粘贴视频链接仍可正常载入。
- 后端命令拒绝空 `mid`、非数字 `mid` 和不合理的 `limit`。
- 文档、TypeScript、Rust 和测试必须通过本仓库质量门禁：

```bash
pnpm run check
```
