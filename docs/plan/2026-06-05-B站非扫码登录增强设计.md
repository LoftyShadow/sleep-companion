# B站非扫码登录增强设计

## 背景

当前 B 站听视频功能只支持 Web 端二维码登录。用户希望登录功能支持非扫码登录，并参考 `/home/niemingzhi/IdeaProjects/BiliPai`，最好可以拉起 B 站登录。

本次核查后得到的边界：

- BiliPai 中存在手机号短信登录和密码登录接口封装，但它依赖 B 站极验验证、短信 `captcha_key`、密码 RSA 加密和风控返回处理。
- BiliPai 当前默认登录实际偏向 TV 端二维码，用于获取 `access_token` 和高画质能力；这不满足“非扫码”的主要目标。
- Tauri 2 当前项目已接入 `tauri-plugin-opener`，可以打开系统浏览器。
- Tauri 2.4 之后提供 WebView Cookie 读取能力；当前 `Cargo.lock` 中 `tauri` 为 `2.11.2`，Rust 侧可读取应用内 WebView 的 Cookie。
- 系统浏览器 Cookie 不能被应用可靠、安全地直接读取。因此“打开默认浏览器登录后自动同步登录态”不作为承诺能力。

## 目标

1. 保留现有扫码登录。
2. 新增“官方网页登录”入口：在 Tauri 应用内打开 B 站官方登录页，由用户在官方页面完成登录。
3. 新增从登录 WebView 捕获 B 站 Cookie 的命令，成功后复用现有本地会话保存和账号摘要获取逻辑。
4. 新增 Cookie 导入兜底：支持用户粘贴浏览器 Cookie 或 `Set-Cookie` 文本，后端验证通过后保存。
5. 前端不接收或显示完整 `SESSDATA`、`bili_jct` 等敏感 Cookie；除用户输入框本身外，不在状态、日志、测试断言中暴露完整凭据。

## 非目标

- 本次不实现应用内手机号短信登录。
- 本次不实现应用内密码登录。
- 本次不尝试读取系统浏览器 Cookie。
- 本次不引入 BiliPai 的 TV 端 `access_token` 登录链路。

这些能力可以后续做，但短信和密码登录意味着应用直接处理账号凭据和验证码风控，安全边界与维护成本都明显高于官方网页登录。

## 方案

### 官方网页登录

- 前端通过 Tauri `WebviewWindow` 打开 `https://passport.bilibili.com/login`。
- 登录窗口使用独立 label，重复点击时优先聚焦已有窗口。
- 用户完成登录后回到主界面点击“同步网页登录”。
- Rust 命令读取该 WebView 中 `https://www.bilibili.com/` 对应 Cookie。
- 后端只保存支持的 B 站 Cookie 字段：`SESSDATA`、`bili_jct`、`buvid3`、`DedeUserID`、`DedeUserID__ckMd5`、`sid`。
- 后端调用 `x/web-interface/nav` 验证登录态；验证失败不保存。

### Cookie 导入

- 前端提供可折叠输入区域，提示用户只粘贴 `Cookie` 或 `Set-Cookie` 文本。
- Rust 支持解析两类文本：
  - `Cookie` 请求头格式：`SESSDATA=...; bili_jct=...`
  - `Set-Cookie` 多行格式：`SESSDATA=...; Path=/; Max-Age=...`
- 后端要求必须存在 `SESSDATA`，并通过 `nav` 接口验证后保存。

## 组件边界

- `src-tauri/src/bilibili_auth.rs`：登录命令、Cookie 解析、网页登录 Cookie 捕获、会话验证与保存。
- `src-tauri/src/lib.rs`：注册新增 Tauri 命令。
- `src/features/videoListening/bilibiliAuth.ts`：前端认证客户端接口与响应规范化。
- `src/features/videoListening/useBilibiliAuth.ts`：登录状态机和新登录动作。
- `src/features/videoListening/BilibiliLoginPanel.tsx`：登录 UI，提供扫码、官方网页登录、Cookie 导入。
- `src/features/videoListening/VideoListeningView.css`：仅补充登录面板局部样式，不扩大到无关页面。

## 风险

- B 站网页登录页可能根据平台风控要求二次验证；这属于官方页面内行为。
- Android 上 Tauri Cookie API 文档说明 WebView Cookie 读取不支持或返回空，因此移动端主要依赖扫码或 Cookie 导入兜底。
- Web 非 Tauri 运行环境没有应用内 WebView Cookie 捕获能力，只能使用已有 Web API 或 Cookie 导入端点；当前没有后端 Web API 扩展时会返回不可用。

## 验收

- 未登录状态下，面板同时提供扫码登录、官方网页登录和 Cookie 导入入口。
- 扫码登录原行为不回归。
- 官方网页登录窗口能被打开；同步命令没有 Cookie 时给出明确提示。
- Cookie 导入通过后展示账号摘要，不在 UI 状态中显示完整 Cookie。
- Rust 单元测试覆盖 Cookie 请求头解析、`Set-Cookie` 解析和缺少 `SESSDATA` 的拒绝路径。
- 前端单元测试覆盖新客户端方法、Hook 登录动作和面板交互。
- 完成后运行 `pnpm run check`。
