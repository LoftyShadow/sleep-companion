# 声音页全局混音工作台重设计

## 背景

当前声音页把白噪音、ASMR 和其他声音拆成三个入口，每个入口又带自己的组合、分类或配置区域。用户在调睡眠声音时看到的是多个来源分组，而不是一个明确的“当前混音”。这会造成两个问题：

- 正在播放的声音分散在不同来源筛选里，用户需要切换来源才能找到并调整某个声音。
- 推荐组合、ASMR 组合、我的混音分别出现在不同语境里，用户会误以为混音是按来源局部保存的。

本次不沿用旧信息架构，按陪伴睡眠软件的实际使用路径重新设计声音页。

## 目标

- 声音页只有一个全局混音工作台，集中展示当前正在播放或待恢复的声音。
- 当前混音中的每个声音都能直接暂停、恢复和调音量，不需要切换到所属来源。
- 推荐组合和我的混音合并为一个“混音方案”入口，所有方案都应用到同一个全局混音。
- 白噪音、ASMR、XMSLEEP 分类和自定义音频只作为同一组声音标签，不拥有自己的当前混音或用户配置。
- XMSLEEP 分类标签只影响声音库列表，不生成分类快混，也不再通过“其他声音”中间入口进入。
- 保留现有 `PlayerPort`、`useSoundMixer`、自定义混音存储和睡眠入口桥接，不做数据迁移。

## 非目标

- 不重写播放器底层。
- 不改变已有音频资源路径。
- 不迁移 `sound-presets/custom-presets.json`。
- 不增加复杂的混音编辑器、排序器、导入导出或跨设备同步。
- 不删除任何声音资源。

## 新信息架构

```text
声音页
  -> 全局混音工作台
       -> 播放 / 停止全局混音
       -> 当前混音声音列表
       -> 每个声音的播放状态和音量控制
  -> 混音方案
       -> 推荐混音方案
       -> 我的混音
       -> 保存当前全局混音
  -> 声音库
       -> 声音标签：全部 / 白噪音 / ASMR / 自然 / 雨声 / 城市 / 场所 / 交通 / 物品 / 噪音 / 动物 / 自定义音频
       -> 单个声音添加 / 暂停 / 音量调整
       -> 自定义音频导入
```

## Component Map

`SoundMixerView`：

- 继续作为声音页编排入口。
- 生成当前混音条目，供全局混音工作台和睡眠入口复用。
- 把推荐方案、我的混音、声音库筛选和播放控制连接到 `useSoundMixer`。

`ActiveMixPanel`：

- 新增组件，集中展示当前混音内的声音。
- 承载全局播放摘要、播放/停止按钮和播放状态，不再拆出独立播放卡。
- 每个条目可暂停、恢复和调音量。
- 当前无声音时显示轻量空态。

`MixPlanPanel`：

- 新增组件，合并推荐混音方案和我的混音。
- 提供保存当前全局混音、应用方案和删除我的混音。
- 不按白噪音、ASMR 或其他声音拆分区域。

`MixerHeader`：

- 改为声音库统一标签筛选器。
- 白噪音、ASMR、XMSLEEP 分类和自定义音频都在同一组标签内展示。
- 标签筛选只影响 `SoundGrid` 展示，不影响当前混音。
- 不再保留“其他声音”一级入口，也不再渲染单独的分类卡片或二级筛选区域。

`SoundGrid`：

- 继续负责声音库卡片和单个声音播放控制。
- 与 `ActiveMixPanel` 共享同一套 `playingSoundIds` 和音量状态。

## 方案取舍

### 方案一：保留三来源布局，只在顶部增加提示

实现成本最低，但不能解决用户需要在三个来源之间找正在播放声音的问题，也继续保留“每个来源都有自己的组合”的心智。

不采用。

### 方案二：把正在播放声音做成浮动抽屉

可以减少页面改动，但当前应用已经有悬浮播放控制，再增加一个声音页抽屉会让操作层级更复杂。

不采用。

### 方案三：声音页改为全局混音工作台

把当前混音、混音方案和声音库拆成三个稳定区域。所有播放和保存都回到全局混音，来源只用于查找声音。这个方案最符合用户“合理好用”的要求。

采用。

## 兼容性

- 用户保存过的我的混音继续读取同一存储文件。
- 推荐方案仍走 `useSoundMixer.applyPreset`。
- 睡眠入口继续接收当前混音快照。
- 自定义音频仍由 `useCustomSounds` 管理。
- 旧的用户可见布局会变化，但不是数据破坏性更新。

## 验收标准

- 声音页默认显示“当前混音”“推荐与我的混音”“声音库”三个核心区域。
- 切换白噪音、ASMR、XMSLEEP 分类或自定义音频标签时，当前混音区域保持可见。
- 播放 ASMR 或 XMSLEEP 分类声音后，不切标签也能在当前混音区域看到并调音量。
- 推荐方案和我的混音位于同一个“混音方案”区域。
- 声音标签只改变声音库列表，不影响当前混音。
- 保存、应用、删除我的混音行为不回归。
- 睡眠入口接收到的当前混音快照不回归。
- 必须通过：

```bash
rtk pnpm run check
```

## 风险

- UI 结构变化会影响既有集成测试的可访问名称，需要同步更新断言。
- 当前混音区域和声音库中可能同时出现同一个声音的控制入口，音量标签必须区分，避免 Testing Library 查询和无障碍名称冲突。
- 移动端需要保持当前混音、混音方案和声音库的顺序清楚，避免横向滚动过多。
