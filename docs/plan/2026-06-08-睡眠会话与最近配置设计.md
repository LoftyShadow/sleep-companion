# 睡眠会话与最近配置设计

## 背景

当前应用已经具备声音混音、听书、听视频和全局定时停止能力，但用户进入睡眠场景时仍需要先到声音页手动恢复组合，再单独设置定时。作为陪伴睡眠软件，第一优先级应把“今晚开始睡觉”做成一个明确入口，并允许用户复用最近几次真实使用过的声音配置。

## 目标

- 新增一级入口“睡眠”，与“声音 / 听书 / 听视频”并列。
- 睡眠入口展示当前可用于入睡的声音配置摘要，具体声音组合和音量仍在“声音”页修改。
- 睡眠入口允许用户决定本次是否纳入听书和听视频。
- 用户可以用当前配置开始睡眠，并同步启动全局定时停止。
- 保存最近 5 次睡眠声音配置，用户可以直接复用。
- 复用最近配置时，由现有声音混音器执行播放，不绕过 `PlayerPort`。
- 保持声音、听书、听视频现有行为不变。

## 第一版范围

包含：

- 新增 `sleep` 应用模式。
- 新增 `SleepSessionView` 睡眠入口。
- 新增最近配置存储，路径为 `sleep-session/recent-configs.json`。
- 最近配置包含声音 ID、展示名称、音量、定时时长、可选模块和最近使用时间。
- 最近配置最多保留 5 条，相同声音组合和音量视为同一配置并上移。
- 支持从当前混音状态保存配置。
- 支持从最近配置恢复播放并启动定时器。
- 睡眠页提供跳转到“声音”页的入口，用于修改声音组合和单个声音音量。
- 支持开关决定是否把听书、听视频纳入本次睡眠会话。
- 听书和听视频的内容准备仍在各自页面完成；睡眠页提供状态和跳转准备入口。
- 支持删除最近配置。

不包含：

- Android 后台或锁屏播放。
- 跨应用重启恢复正在运行的倒计时。
- 在睡眠页内添加、移除声音或调整单个声音音量。
- 在睡眠页内编辑听书书稿、TTS 声音、B 站链接或视频源。
- 医学级睡眠评分或传感器数据分析。
- 淡出播放的实际音量曲线实现；本阶段只保留文档和接口边界，后续单独实现。

## 架构边界

睡眠入口不直接操作播放器实例，只向工作台发出“播放某个声音配置”的请求：

```text
SleepSessionView
  -> AppWorkspace 记录请求
  -> SoundMixerView 消费请求
  -> useSoundMixer 按配置停止旧声音并播放新声音
  -> PlayerPort
```

最近配置存储独立在 `features/sleepSession` 下，使用已有 `FileSystemPort`。这样 Web、桌面和 Android 端可以复用同一套存储边界。

## 数据模型

```ts
interface SleepSoundConfigItem {
  soundId: SoundId;
  name: string;
  volume: number;
}

interface RecentSleepSoundConfig {
  id: string;
  title: string;
  items: SleepSoundConfigItem[];
  enabledModules: {
    audiobook: boolean;
    video: boolean;
  };
  durationMinutes: number;
  createdAt: number;
  updatedAt: number;
}
```

`id` 使用配置内容和可选模块生成，不使用随机值。这样相同组合再次保存时能稳定去重。

## Component Map

`AppWorkspace`：

- 维护当前应用模式。
- 挂载睡眠入口。
- 保存声音混音器上报的当前配置快照。
- 把睡眠入口的播放请求转发给声音混音器。

`SoundMixerView`：

- 继续维护声音播放状态和 UI。
- 向外上报当前可复用的声音配置快照。
- 消费来自睡眠入口的配置播放请求。

`useSoundMixer`：

- 新增按声音配置播放的动作。
- 继续保持音量、播放中声音和恢复声音 ID 的内部一致性。

`SleepSessionView`：

- 展示当前配置、可选模块、定时控制和最近配置列表。
- 提供“去声音页配置”入口，不直接编辑声音组合或音量。
- 调用最近配置 hook。
- 不直接依赖 `PlayerPort`。

`sleepSessionStore`：

- 负责最近配置的读取、校验、去重、排序、删除和持久化。

## 方案取舍

### 方案一：睡眠入口直接创建独立播放器

优点是实现路径短。缺点是会绕过现有混音器状态、定时停止、浮动控制和跨平台播放器抽象，容易造成同一个声音被两个播放器同时管理。

不采用。

### 方案二：睡眠入口只作为混音器控制面板

优点是复用现有 `PlayerPort` 和声音状态，风险较低。缺点是需要让混音器上报快照并消费播放请求。

采用。

### 方案三：把最近配置做成声音预设

优点是概念统一。缺点是当前 `SoundPreset` 是静态内置预设，不负责用户最近使用记录；直接混入会让预设和历史记录职责混杂。

不采用。

## 失败路径

- 存储文件不存在：返回空列表。
- 存储内容损坏：忽略损坏内容，返回空列表。
- 最近配置引用的声音不存在：播放时由混音器过滤不可用声音。
- 配置内所有声音都不可用：不发起播放，并显示轻量错误。
- 用户勾选听书但听书未准备好：不发起听书播放，提示去听书页准备。
- 用户勾选听视频但视频未载入：不发起听视频播放，提示去听视频页准备。
- 保存当前配置时没有可用声音：禁用保存和开始按钮。

## 兼容性

本阶段没有破坏性更新：

- 不修改 `PlayerPort` 方法签名。
- 不修改 Tauri 命令签名。
- 不修改已有声音资源路径。
- 不修改已有定时停止公共行为。

## 验收标准

- 应用模式切换中出现“睡眠”入口。
- 可以进入睡眠入口并看到当前声音配置摘要。
- 点击“去声音页配置”会回到“声音”页修改具体配置。
- 睡眠入口不出现添加声音、移除声音或单个声音音量滑杆。
- 当前配置可保存到最近配置。
- 最近配置最多保留 5 条。
- 重复保存同一配置不会生成重复项，而是更新最近使用时间。
- 点击最近配置会恢复对应声音组合和音量。
- 从睡眠入口开始会启动全局定时停止。
- 睡眠入口可以勾选或取消听书、听视频。
- 已准备好的听书或听视频被勾选时，开始睡眠会请求对应模块播放。
- 未准备好的听书或听视频被勾选时，睡眠入口提供去准备入口。
- 原“声音 / 听书 / 听视频”切换和浮动控制行为不回归。
- 必须通过：

```bash
rtk pnpm run check
```
