# 睡眠入口行为修复与结构优化设计

## 背景

睡眠入口和最近配置已经接入，但代码审查发现三个需要立即修正的问题：

- 睡眠入口使用模块“切换”请求启动听书和听视频，若模块已经播放，可能被反向暂停。
- 最近配置复用没有复用当前配置启动时的模块可用性校验。
- 最近配置 hook 对保存和删除失败缺少错误捕获。

同时 `SleepSessionView` 已经承担格式化、模块状态判断、保存复用流程和完整 JSX 渲染，后续继续扩展会加重维护成本。

## 目标

- 睡眠入口启动已勾选模块时，只对未播放但可播放的模块发起播放请求。
- 已经处于播放中的听书或听视频不被“开始睡眠”反向暂停。
- 当前配置启动和最近配置复用使用同一套模块可用性判断。
- 最近配置包含未准备模块时，“复用”不能直接启动睡眠会话。
- 最近配置保存和删除失败时，页面显示错误，不产生未处理异步异常。
- 拆分 `SleepSessionView` 的动作逻辑和列表渲染，降低单文件复杂度。

## 第一版范围

包含：

- 新增工作台层面的“确保模块播放”入口。
- 睡眠入口改用“确保播放”语义，而不是复用通用 toggle 语义。
- 抽取睡眠模块可用性判断 helper。
- 抽取睡眠页动作 hook，集中管理保存、开始、复用和模块开关。
- 抽取最近配置列表组件。
- 补充覆盖已播放模块、未准备最近配置、存储失败的测试。

不包含：

- 改造听书或听视频内部播放器 API。
- 新增后台播放、淡出播放或睡眠历史。
- 在睡眠页编辑声音组合、听书内容或视频来源。
- 更改 `PlayerPort`、Tauri 命令或 Android 播放接口。

## 架构边界

```text
SleepSessionView
  -> useSleepSessionActions 处理开始 / 保存 / 复用 / 模块选择
  -> canStartSleepModules 判断模块是否可以纳入会话
  -> RecentSleepConfigList 渲染最近配置列表
  -> AppWorkspace.handleStartSleepModules / shouldStartSleepModule 只启动未播放模块
  -> usePlaybackControlBus 发起模块播放请求
```

睡眠页仍然不直接操作播放器实例。听书和听视频继续通过播放控制总线通信，但睡眠入口只发送“需要启动”的请求，不对已经播放中的模块发 toggle。

## 实施结果

- `AppWorkspace` 已增加睡眠模块可用性和可启动状态判断，只对 `idle`、`loaded`、`paused` 且可用的听书或听视频发送启动请求。
- `SleepSessionView` 已拆分为页面编排组件，最近配置列表、动作流程和纯格式化函数分别移入独立文件。
- 当前配置启动和最近配置复用已共用 `canStartSleepModules` 校验。
- 最近配置保存和删除失败已通过 `useRecentSleepConfigs` 捕获，并由页面错误区域展示。
- 已补充应用层回归测试，覆盖已播放听书、已播放视频、最近配置未准备模块、保存失败和删除失败。

## 方案取舍

### 方案一：在 `SleepSessionView` 内判断并直接避免调用已播放模块

实现最小，但会把播放控制语义散落在视图组件中，后续浮动控制或其他入口无法复用。

不采用。

### 方案二：在 `AppWorkspace` 增加确保播放语义

`AppWorkspace` 已经持有模块播放状态和请求入口，由它过滤已播放、不可用和不可切换模块最直接。睡眠页只表达“本次会话需要这些模块”。

采用。

### 方案三：修改播放控制总线，把 toggle 改成 start

会影响浮动控制和既有模块按钮，容易造成行为回归。

不采用。

## 验收标准

- 听书已经播放时，勾选听书开始睡眠不会暂停听书。
- 听视频已经播放时，勾选听视频开始睡眠不会暂停视频。
- 当前配置勾选未准备听视频时，“开始睡眠”保持禁用。
- 最近配置包含未准备听视频时，“复用”保持禁用或不可启动。
- 最近配置包含已准备模块时，可以复用并启动对应声音配置和定时器。
- 最近配置保存失败时显示错误消息。
- 最近配置删除失败时显示错误消息。
- `SleepSessionView` 不再直接承载最近配置列表渲染和主要动作流程。
- 必须通过：

```bash
rtk pnpm run check
```

阶段性目标验证：

```bash
rtk pnpm exec tsc -b --pretty false
rtk pnpm exec vitest run src/features/appMode/AppWorkspace.test.tsx src/features/sleepSession/sleepSessionStore.test.ts --no-file-parallelism
```

上述目标验证已通过。全量 `rtk pnpm run check` 已通过。

## 风险

- 如果只过滤 `playing` 状态，`loading` 状态可能仍被错误触发；本次判断要同时尊重 `canToggle` 和 `unavailable`。
- 最近配置复用的按钮状态要能随模块准备状态变化刷新。
- 抽 hook 时不要改变最近配置保存去重逻辑。

## 破坏性更新说明

无破坏性更新。本次修复用户可见行为，但不修改持久化数据结构、播放器接口或资源路径。
