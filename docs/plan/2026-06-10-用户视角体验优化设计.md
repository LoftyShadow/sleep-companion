# 用户视角体验优化设计

## 背景

基于 Chrome MCP 对 Web 版桌面与移动视口的巡检，本次优化聚焦用户能直接感知的路径：

- 声音页默认暴露 119 个声音，查找和读屏浏览成本偏高。
- 听视频的 UP 主公开视频刷新依赖 B 站网络，慢请求期间反馈不够明确。
- 听书遇到长书名时，视觉标题和按钮可访问名称过长。
- 睡眠页能力完整，但主路径和高级设置层级不够分明。
- Chrome DevTools 对部分 `input` 控件提示缺少稳定 `id` 或 `name`。

## 目标

- 降低声音页首屏和移动端信息密度，让用户更快找到可播放声音。
- 让 B 站 UP 主刷新在慢网络下可理解、可重试，不像卡死。
- 缩短听书长标题在视觉和辅助技术中的干扰。
- 强化睡眠页“今晚开始”的主路径，把高级模块收束到可展开区域。
- 修补常用表单控件的 `id` 和 `name`，减少 DevTools issue。

## 执行原则

- 先完成全部文档和任务清单，再进入代码实现。
- 按步骤文档顺序执行，不跳步、不混入下一步范围。
- 每一步提交前先查看 status、diff 和暂存内容。
- 每一步提交只包含该步骤文档允许的文件。
- 发现步骤文档不合理时，先更新文档，再继续实现。
- 每个实现步骤完成后至少跑目标测试；最后统一跑 `pnpm run check`。
- 最终推送前确认 `main...origin/main` 状态和提交列表。

## 非目标

- 不改声音文件、音源目录和播放协议。
- 不新增第三方依赖。
- 不改 B 站接口能力边界，不绕过 B 站风控。
- 不重做整站视觉风格，不引入新的设计系统。
- 不改 Tauri/Rust 原生播放架构。

## 用户路径

### 声音

用户打开应用后，优先看到当前混音、推荐方案和少量最相关声音。用户可以搜索声音名称或分类；完整声音库仍可展开查看。

### 听视频

用户打开 UP 主面板并刷新时，页面会显示正在请求、等待较久时的说明，以及失败后的重试入口。请求成功后保持当前分页能力。

### 听书

用户导入或继续阅读长标题书籍时，页面保持可读的短标题；完整标题仍可通过原生悬停或详情查看。删除、打开等操作的辅助技术文案不再读出过长标题。

### 睡眠

用户进入睡眠页时，首屏优先完成“当前配置 + 开始睡眠”。会话模块、定时和最近配置仍可使用，但层级更接近高级设置。

## Component Map

- `SoundMixerView`：声音页编排、搜索状态、完整声音库展开状态。
- `SoundGrid`：声音卡片渲染、音量控件标识。
- `BilibiliCreatorPanel`：UP 主列表、公开视频分页、慢请求提示。
- `useBilibiliCreators`：刷新状态、慢请求计时、错误状态。
- `AudiobookView`：当前朗读标题展示。
- `AudiobookLibraryPanel`：书架项标题、打开和删除按钮文案。
- `SleepSessionView`：睡眠页主路径、高级区块折叠。
- `VideoNowPanel`、`VideoProgressControls`：视频表单控件标识。
- CSS 文件：只在对应 feature 样式文件内调整布局和状态。

## 方案

### 声音库

采用“搜索 + 默认精选 + 展开完整库”的轻量方案。默认不渲染全部 119 个声音，只展示当前筛选下的前一批声音；用户可以搜索或点击“显示全部”查看完整列表。这样不引入虚拟列表库，也避免大范围重构。

### UP 主刷新

保留现有 loader 和分页数据结构，在 hook 内增加慢请求计时状态。请求超过阈值后更新状态文案；失败后保留刷新按钮可重试。第一版不做真正 Abort 取消，因为当前 loader 和 Tauri 命令没有统一取消协议。

### 听书标题

新增纯函数截断标题，视觉层使用短标题和 `title` 保存完整标题；按钮可访问名称使用短标题。正文数据不变，不影响进度存储。

### 睡眠页

保留所有功能，默认突出主操作。把会话模块、定时和最近配置放入“更多设置”区域或更明确的高级层级。用户仍能直接进入声音页、听书、听视频准备内容。

### 表单控件

给动态 range/file/select 控件补稳定 `id` 和 `name`。动态声音 id 进入属性前使用已有业务 id 组合，避免随机 id 导致测试不稳定。

## 破坏性更新

无。所有改动仅影响 UI 展示、状态提示和表单属性，不迁移本地数据，不改变持久化格式。

## 验收标准

- 声音页默认不把全部声音卡片直接渲染到首屏；搜索能按名称或分类缩小结果。
- 声音页仍可播放推荐混音和单个声音，音量可调。
- UP 主刷新超过慢请求阈值时有明确等待提示；失败时仍可重试。
- UP 主分页仍以 `page=1&pageSize=5` 请求并展示 5 条。
- 听书长标题视觉不撑开布局；打开和删除按钮的可访问名称使用短标题。
- 睡眠页主操作仍可启动当前声音配置；高级模块仍可使用。
- Chrome DevTools 不再提示本次覆盖控件缺少 `id` 或 `name`。
- 代码最终通过 `pnpm run check`。

## 风险

- 声音库默认折叠后，少数用户可能以为声音变少；需要明确“显示全部”和搜索结果计数。
- UP 主慢请求阈值只能改善感知，不能保证 B 站接口稳定。
- 睡眠页折叠高级内容可能影响熟练用户一步到位，需要保留可见入口。
