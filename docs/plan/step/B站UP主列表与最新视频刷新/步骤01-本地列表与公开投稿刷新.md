# 步骤01：本地列表与公开投稿刷新

## 目标

完成第一版功能实现：用户保存 UP 主，刷新最新公开视频，并点击视频接入现有官方播放器。

## 涉及文件

- `src/features/videoListening/bilibiliCreator.ts`
- `src/features/videoListening/bilibiliCreatorStore.ts`
- `src/features/videoListening/useBilibiliCreators.ts`
- `src/features/videoListening/BilibiliCreatorPanel.tsx`
- `src/features/videoListening/VideoListeningView.tsx`

- `src/features/appMode/AppWorkspace.tsx`
- `src-tauri/src/bilibili_metadata.rs`
- `src-tauri/src/lib.rs`
- 相关测试文件

## 输入输出

输入：

- B 站 UP 主主页链接。
- 数字 `mid`。
- 用户点击刷新、删除和视频播放按钮。

输出：

- 本地 UP 主列表。
- 当前 UP 主最新公开视频列表。
- 选中视频对应的官方播放器状态。

## 风险点

- B 站 WBI 签名动态分页接口可能返回空列表、风控错误或结构变化。
- WBI 投稿兜底接口可能因为签名规则变化或风控策略失败。
- IndexedDB 不可用时无法保存本地列表。
- JSDOM 测试环境没有真实 Tauri 后端，必须通过可注入 loader 覆盖。
- Web 开发和预览环境没有 Tauri `invoke`，必须通过本地 API 代理刷新 UP 主视频。

## 验收标准

- `parseBilibiliCreatorInput` 能解析空间链接和数字 `mid`。
- `bilibiliCreatorStore` 能保存、加载、去重、删除。
- `useBilibiliCreators` 能在添加后选择 UP 主并刷新公开视频。
- 点击视频后 `VideoListeningView` 载入对应 `BV` 播放源。
- Rust 单元测试覆盖 WBI 参数构造、投稿响应解析和动态视频解析。
- Web API 代理可以用 `/api/bilibili/creator-videos?mid=15810&limit=12` 获取 `Mr.Quin` 的最多 12 条公开视频。
- Linux/Tauri 后端可以用外网集成测试验证 `mid=15810` 的分页刷新路径。
- 必须运行 `pnpm run check`。
