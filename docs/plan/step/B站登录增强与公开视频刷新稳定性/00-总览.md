# B站登录增强与公开视频刷新稳定性总览

## 目标

在现有 UP 主公开视频刷新能力上增加可选 B 站 Web 二维码登录。登录后，刷新链路使用本地保存的网页会话请求 B 站投稿分页接口，以降低匿名接口 HTTP 412 的概率。当前策略不再请求 B 站动态接口兜底。

## 步骤列表

1. 后端登录会话与刷新链路设计落地。
2. 前端登录状态和二维码面板接入。
3. 登录态刷新、匿名降级和错误提示联调。
4. 测试、文档同步和最终验证。

## 执行顺序

- 先实现后端会话模型、二维码命令、会话存储和请求上下文。
- 再实现前端 `bilibiliAuth.ts`、`useBilibiliAuth` 和 `BilibiliLoginPanel`。
- 然后把 `fetch_bilibili_creator_videos` 接入登录态优先刷新策略。
- 最后补齐测试和运行仓库质量门禁。

## 统一验收标准

- 未登录时现有匿名刷新不退化。
- 登录成功后，刷新请求能使用后端保存的 B 站会话。
- Web 环境刷新页面或重新进入同一个 dev/preview server 后，能复用未过期登录态，不要求用户每次扫码。
- 前端不能读取或展示敏感 cookie。
- 退出登录会清理本地会话。
- 失败信息能区分匿名刷新和登录态刷新。
- 完成代码后必须运行 `pnpm run check`。

## 全局风险

- B 站 Web 登录和网页接口可能变化。
- HTTP 412 可能来自多种风控条件，登录只能降低概率，不能保证完全消除。
- 本地会话文件需要避免日志、错误提示和前端 API 泄露。
- Android 真机二维码登录和本地文件权限需要单独验证。

## 破坏性更新说明

本任务不做破坏性更新：

- 不迁移已有 UP 主列表。
- 不移除匿名刷新。
- 不改变现有 B 站 iframe 播放。
- 不影响本地音频、听书和全局播放控制。
