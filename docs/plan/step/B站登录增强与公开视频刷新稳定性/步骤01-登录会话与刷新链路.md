# 步骤01：登录会话与刷新链路

## 目标

完成 B 站 Web 二维码登录的后端设计落地，并把 UP 主公开视频刷新链路改成登录态优先、匿名兜底。

- `src-tauri/src/bilibili_common.rs`
- `src-tauri/src/bilibili_session.rs`
- `src-tauri/src/bilibili_metadata.rs`
- `src-tauri/src/lib.rs`

- `src/features/videoListening/useBilibiliAuth.ts`
- `src/features/videoListening/BilibiliLoginPanel.tsx`
- `src/features/videoListening/BilibiliCreatorPanel.tsx`
- `src/features/videoListening/VideoListeningView.css`
- 相关测试文件

## 输入输出

输入：

- 用户点击“扫码登录”。
- 用户使用 B 站客户端扫描二维码并确认。
- 用户点击“刷新视频”。
- 用户点击“退出登录”。

输出：

- 登录二维码 URL 或前端可渲染二维码数据。
- 登录轮询状态。
- 前端可见账号摘要。
- 登录态或匿名模式下的 UP 主公开视频列表。
- 明确区分刷新模式的错误信息。

## 实现边界

- 只做 Web 二维码登录。
- 不做手机号、密码、TV 登录和 `access_token` 刷新。
- 不让前端接触真实 cookie。
- 不改动现有 UP 主列表持久化结构。
- 不增加 B 站私有资源读取能力。
- Web 环境不把 cookie 放入 IndexedDB、`localStorage` 或 `sessionStorage`，只允许 Vite 代理写入本机缓存文件。

## 后端任务

- 新增二维码创建命令 `create_bilibili_login_qr`。
- 新增二维码轮询命令 `poll_bilibili_login_qr`。
- 新增登录状态命令 `get_bilibili_auth_status`。
- 新增退出登录命令 `logout_bilibili`。
- 解析登录成功响应头中的 `SESSDATA`、`bili_jct`、`DedeUserID`、`DedeUserID__ckMd5`、`sid`、`buvid3` 和过期时间。
- 登录成功后请求 `x/web-interface/nav` 补齐账号摘要；如果摘要请求失败，至少保存 `SESSDATA` 并显示为已登录但账号信息待刷新。
- Web 调试和预览环境登录成功后，把最小会话字段保存到用户级缓存目录；状态查询、UP 主刷新、直连音频解析和音频代理都先加载缓存再构造 cookie。
- Web 调试和预览环境退出登录时删除缓存文件；缓存损坏、缺少 `SESSDATA` 或过期时自动按未登录处理并清理。
- 建立 `BilibiliRequestContext`，统一注入 cookie、`User-Agent`、`Origin` 和 `Referer`。
- 更新 `fetch_bilibili_creator_videos`：有登录态时登录态优先，无登录态时匿名刷新。

## 前端任务

- 新增 `bilibiliAuth.ts`，封装 Tauri 登录命令和响应校验。
- 新增 `useBilibiliAuth`，管理登录状态、二维码创建、轮询、退出。
- 新增 `BilibiliLoginPanel`，展示未登录、等待扫码、已扫码、已登录、过期和失败状态。
- 在 `BilibiliCreatorPanel` 顶部接入登录面板。
- 刷新失败时保留后端错误原文，不把登录态失败吞成“没有公开视频”。

## 测试要求

- Rust 单元测试：
  - `Set-Cookie` 解析。
  - 登录轮询状态解析。
  - 会话脱敏输出。
  - 登录态 cookie 注入。
  - 匿名模式不注入 `SESSDATA`。
- TypeScript 单元测试：
  - `bilibiliAuth.ts` 响应校验。
  - `useBilibiliAuth` 的成功、过期、退出状态转换。
  - `BilibiliLoginPanel` 不渲染 cookie 字段。
- 集成验证：
  - 没有登录态时，现有 UP 主刷新调用仍可触发。
  - 有登录态时，刷新错误包含“登录态刷新”或成功返回视频。
