# 代码结构深度拆分优化总览

## 目标

把本次结构优化拆成可验证的小步骤，先降低前端 `听视频` 模块复杂度，再统一 Rust B 站请求层，最后做低风险渲染和 Android 播放优化。

## 执行状态

1. 拆分视频预览面板：已完成。
2. 拆分听视频页面 controller 和展示组件：已完成。
3. 统一 Rust B 站 HTTP/WBI helper：已完成，`bilibili_auth.rs`、`bilibili_direct_audio.rs` 和 `bilibili_metadata.rs` 均使用统一 client 构造。
4. 优化声音网格单卡片渲染边界：已完成。
5. 缓存 Android raw 资源 ID：已完成。
6. 运行完整质量门禁并核对文档：已完成。

## 统一验收标准

- 不改变现有用户可见文案和交互语义，除非现有测试要求同步。
- 不改变 Tauri 命令签名。
- 不改变音频资源路径和 raw 资源名。
- 每步完成后至少运行对应目标测试或静态检查；最终运行 `rtk pnpm run check`。
- 文档和代码保持一致。

## 全局风险

- 前端拆分可能改变 React hook dependencies，需要用现有测试保护播放控制和视频 fallback 行为。
- Rust 请求 helper 可能改变请求 header 或 cookie 更新时机，需要尽量做机械抽取。
- Android Kotlin 代码没有独立 JVM 单测，最终主要依赖 `rtk pnpm run check` 中的 Rust/前端门禁和编译链路；Android 真机验证不在本步骤内。
