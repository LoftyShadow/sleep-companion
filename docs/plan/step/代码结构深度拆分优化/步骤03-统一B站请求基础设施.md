# 步骤03：统一 B 站请求基础设施

## 目标

把重复的 B 站 client 构造、JSON 请求、WBI key 拉取和状态码校验下沉到 `bilibili_common.rs`。

## 涉及文件

- `src-tauri/src/bilibili_common.rs`
- `src-tauri/src/bilibili_direct_audio.rs`
- `src-tauri/src/bilibili_metadata.rs`
- `src-tauri/src/bilibili_auth.rs`

其中 `bilibili_auth.rs` 只接入统一 client 构造；二维码、轮询、网页登录同步和 Cookie 导入的响应解析保持原模块内实现。

## 输入输出

- 输入：各业务模块的 URL、Referer、Origin、cookie store 和错误上下文。
- 输出：业务模块仍返回相同结构和相同 Tauri 命令结果。

## 验收标准

- WBI key 拉取只保留一份实现。
- `bilibili_auth.rs`、`bilibili_direct_audio.rs` 和 `bilibili_metadata.rs` 的 `reqwest::Client` 构造使用统一 helper。
- JSON 请求 helper 不吞掉 HTTP 状态错误。
- Rust 测试通过。

## 检查清单

- [x] Referer 和 Origin 保持原语义。
- [x] cookie 写入顺序保持原语义。
- [x] 错误消息仍带业务上下文。
- [x] 不改变 Tauri 命令签名。
- [x] 运行 Rust 检查，最终已通过 `rtk pnpm run check`。
