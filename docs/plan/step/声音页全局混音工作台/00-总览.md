# 声音页全局混音工作台总览

## 目标

把声音页从“白噪音、ASMR、其他声音三套局部入口”改成“一个全局混音工作台”。用户先看到当前混音，再选择混音方案或从声音库添加声音。声音库使用统一标签筛选，不再用“其他声音”作为中间入口，也不承载用户配置或正在播放状态。

## 执行步骤

1. 设计文档同步：写入全局混音工作台设计，明确新信息架构和验收标准。
2. 状态和声音标签整理：把声音库模式改成统一标签筛选，增加“全部”和“自定义”，移除模式级组合语义。
3. 全局混音工作台：新增当前混音列表组件，集中展示正在播放或待恢复的声音。
4. 混音方案合并：新增混音方案组件，把推荐方案和我的混音放到同一区域。
5. 页面布局重构：移除旧侧栏结构，把当前混音、混音方案、声音库整理为稳定三段。
6. 测试和验证：同步集成测试、运行目标测试、IDE inspection 和全量 `rtk pnpm run check`。

## 统一验收标准

- 当前混音区域始终可见。
- 当前混音区域能显示跨白噪音、ASMR、其他声音和自定义音频的声音。
- 当前混音条目能播放、暂停和调音量。
- 推荐方案和我的混音不再分别挂在不同来源模式下。
- 声音库标签筛选只影响候选声音列表。
- XMSLEEP 分类直接作为声音标签出现，不再保留“其他声音”入口或独立分类区块。
- 旧的模式级组合侧栏不再出现。
- 最终运行 `rtk pnpm run check`。

## Component Map

Page / Route：

- `SoundMixerView`：声音页编排、播放器状态、保存快照和跨模块桥接。

Feature Component：

- `ActiveMixPanel`：当前混音摘要、播放控制、条目和音量控制。
- `MixPlanPanel`：推荐方案和我的混音。
- `MixerHeader`：声音库统一标签筛选。

Leaf Component：

- `SoundGrid`：声音卡片。
- `CustomAudioPanel`：自定义音频导入。

Hook：

- `useSoundLibraryState`：标签筛选和可见声音派生。
- `useSoundMixer`：播放状态、音量、方案应用和全局停止。
- `useCustomSoundPresets`：我的混音持久化。

Style File：

- 新增 `ActiveMixPanel.css` / `ActiveMixPanel.mobile.css`。
- 新增 `MixPlanPanel.css` / `MixPlanPanel.mobile.css`。
- 更新 `SoundMixerView.css` / `SoundMixerView.mobile.css`。
- 更新 `MixerHeader.css` / `MixerHeader.mobile.css`。

## 破坏性更新说明

无数据级破坏性更新。用户可见变化是声音页布局重排：旧的白噪音、ASMR、其他声音模式级组合侧栏会被全局混音工作台、混音方案区域和统一声音标签替代。回滚方式是恢复本次 UI 组件和布局改动；用户保存数据不需要迁移。

## 风险

- 同一个声音会同时出现在当前混音和声音库中，必须使用不同的音量 `aria-label`。
- 推荐方案从来源分组中抽出后，测试不能再依赖“ASMR 预设”标题。
- 删除旧侧栏组件时要确认没有残留 import。
