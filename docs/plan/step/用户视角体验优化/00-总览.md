# 用户视角体验优化总览

## 目标

按用户视角审查结果分步骤优化声音、听视频、听书和睡眠页体验，并保持每一步可验证、可回滚、可独立提交。

## 步骤列表

| 顺序 | 文档 | 状态 | 提交边界 |
| --- | --- | --- | --- |
| 1 | `步骤01-文档和验收基线.md` | 已完成 | 只提交文档和任务清单 |
| 2 | `步骤02-声音库查找与默认展示密度.md` | 未开始 | 只提交声音页相关代码、样式和测试 |
| 3 | `步骤03-B站UP主刷新等待与重试反馈.md` | 未开始 | 只提交听视频 UP 主刷新相关代码、样式和测试 |
| 4 | `步骤04-听书长标题和表单控件可访问性.md` | 未开始 | 只提交听书标题和表单控件标识相关代码、样式和测试 |
| 5 | `步骤05-睡眠页主路径优化与最终验证.md` | 未开始 | 只提交睡眠页相关代码、样式和测试；最后推送 |

## 统一验收标准

- 每一步完成后至少运行对应目标测试或类型检查。
- 所有代码步骤完成后必须运行 `pnpm run check`。
- 文档与实现不一致时先更新文档再继续。
- 不引入新依赖，不改变本地数据结构。
- 每一步提交只包含该步骤相关文件。
- 每一步提交前必须执行 `rtk git status --short --branch` 和相关 diff 检查。

## 执行顺序

1. 完成并固定全部文档。
2. 步骤 02 到步骤 05 逐步实现。
3. 每个步骤实现后运行目标验证。
4. 每个步骤验证后精确暂存并提交。
5. 最后运行 `pnpm run check`、Chrome MCP 冒烟和 `git status`。
6. 推送 `origin/main`。

## 任务看板

完整任务看板见同目录 `任务清单.md`。实现过程中只更新状态，不改变已确认的目标；如果必须调整目标，先更新本总览和对应步骤文档。

## 破坏性更新

无。

## 全局风险

- B 站接口依赖外部网络和风控，体验优化不能替代服务稳定性。
- 当前浏览器里已有本地存储数据，截图和人工巡检可能包含用户已有数据。
- 移动端视口需要额外确认悬浮控制不会遮挡主按钮。
