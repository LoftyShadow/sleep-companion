# 睡眠会话与最近配置总览

## 目标

新增“睡眠”一级入口，让用户可以在睡眠页统一开始睡眠、决定是否纳入听书和听视频，并复用最近几次睡眠配置。声音组合和单个声音音量仍在“声音”页修改；第一版也不在睡眠页编辑听书书稿或 B 站链接，只负责是否把已准备好的模块纳入本次睡眠会话。

## 执行步骤

1. 睡眠入口与应用模式接入：已完成。
2. 最近配置存储与 hook：已完成。
3. 混音器配置快照和播放请求桥接：已完成。
4. 睡眠页交互、定时启动和最近配置复用：已完成，已支持模块开关、声音配置摘要和跳转配置入口。
5. 淡出能力边界预留：已完成。
6. 测试补充和全量验证：测试补充已完成，等待最终全量验证。

## 统一验收标准

- 新入口不破坏原三个模式的切换。
- 最近配置最多保留 5 条。
- 相同声音组合和音量重复保存时只更新已有记录。
- 最近配置恢复时会播放对应声音并使用配置内音量。
- 睡眠页展示当前声音配置摘要，并提供回到“声音”页修改配置的入口。
- 睡眠页不出现添加声音、移除声音或单个声音音量滑杆。
- 睡眠页可以决定是否纳入听书和听视频。
- 听书和听视频未准备好时，睡眠页提供去对应页面准备的入口。
- 未准备好的听书或听视频被勾选时，不能开始会话，避免盲目打开或播放空内容。
- 睡眠入口启动会复用全局定时停止，而不是另建定时器。
- 代码和文档保持一致。
- 最终运行 `rtk pnpm run check`。

## 全局风险

- `SoundMixerView` 长期挂载，新增上报快照时要避免无意义循环渲染。
- 配置播放请求需要只消费一次，避免因为父组件重渲染重复播放。
- 最近配置存储要容忍损坏 JSON 和过期声音 ID。
- 睡眠入口是新一级模式，桌面和移动端导航列数都要同步调整。
- 淡出不是本阶段的实际播放能力，文档和 UI 不能暗示已经支持淡出。
- 睡眠页只在当前处于“睡眠”模式时挂载，避免隐藏页面中的定时器输入影响全局定时控制查询；最近配置通过持久化恢复。

## 破坏性更新说明

无破坏性更新。新增模式、存储文件和组件均为向后兼容改动。
