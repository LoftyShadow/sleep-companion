# 睡眠入口行为修复与结构优化总览

## 目标

修复睡眠入口中模块启动语义和最近配置复用不一致的问题，并降低 `SleepSessionView` 的结构复杂度。修复后，睡眠入口应只启动需要启动的模块，不暂停已经播放的听书或听视频；最近配置复用也必须遵守模块可用性校验。

## 执行步骤

1. 已完成：播放语义修复。在工作台层增加“确保模块播放”语义，睡眠入口不再直接使用 toggle 语义启动模块。
2. 已完成：模块可用性统一。抽取睡眠模块校验 helper，让当前配置和最近配置复用共用判断。
3. 已完成：最近配置错误处理。补充保存和删除失败捕获，页面显示错误。
4. 已完成：结构拆分。抽取 `useSleepSessionActions`、`sleepSessionViewModel` 和 `RecentSleepConfigList`，让 `SleepSessionView` 只保留页面编排。
5. 已完成：测试和验证。已补充行为测试、错误测试和目标测试，并已运行全量检查。

## 统一验收标准

- 已播放的听书或听视频被勾选后，开始睡眠不会把它暂停。
- 未准备的听书或听视频被勾选后，当前配置不能开始。
- 最近配置包含未准备模块时不能直接复用启动。
- 最近配置保存失败和删除失败会显示错误。
- 最近配置正常保存、复用、删除行为不回归。
- `SleepSessionView` 文件职责变窄，列表和动作逻辑拆到独立边界。
- 最终运行 `rtk pnpm run check`。

## 全局风险

- 播放控制总线仍保留 toggle 语义给浮动控制使用，不能把已有浮动控制行为改坏。
- 最近配置复用会更新最近使用时间，修复时不能破坏去重逻辑。
- 拆分组件时要保持可访问名称稳定，避免测试和用户辅助技术体验回归。
