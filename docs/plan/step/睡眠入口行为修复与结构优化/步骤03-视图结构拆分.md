# 步骤03-视图结构拆分

## 状态

已完成，已通过全量检查确认。

## 目标

降低 `SleepSessionView` 的职责和行数，让它只负责页面编排和少量模块选择渲染，动作流程、最近配置列表和纯格式化逻辑进入独立边界。

## 涉及文件

- `src/features/sleepSession/SleepSessionView.tsx`
- `src/features/sleepSession/useSleepSessionActions.ts`
- `src/features/sleepSession/RecentSleepConfigList.tsx`
- `src/features/sleepSession/sleepSessionViewModel.ts`
- `src/features/sleepSession/SleepSessionView.css`

## 组件结构

```text
SleepSessionView：睡眠页页面编排、模块选择区和定时器入口
useSleepSessionActions：当前配置保存、开始睡眠、最近配置复用、模块勾选状态
RecentSleepConfigList：最近配置列表渲染、复用按钮禁用态、删除入口
sleepSessionViewModel：格式化、模块状态文案、模块可启动判断
SleepSessionView.css：沿用既有样式边界，补充按钮禁用态
```

## 输入和输出

输入：

- 当前声音配置。
- 模块播放状态。
- 最近配置 hook 返回的配置列表和操作函数。

输出：

- `SleepSessionView` 不再直接承载最近配置列表渲染和主要异步动作流程。
- UI 文案、按钮名称、区域 `aria-label` 保持稳定。
- 禁用的“复用”按钮拥有明确禁用样式。

## 依赖顺序

本步骤依赖步骤02的 helper 和错误处理逻辑。拆分必须在测试补充前完成，避免测试绑定到已经计划迁移的内部结构。

## 风险点

- 拆分后事件处理器闭包要保持最新的配置项和模块选择。
- 最近配置列表不能改变“复用”“删除”等可访问名称。
- 不为单次使用的小 JSX 继续过度拆分，避免制造目录噪音。

## 验收标准

- `SleepSessionView` 文件职责明显变窄。
- 最近配置列表独立渲染。
- 动作逻辑集中在 `useSleepSessionActions`。
- 纯格式化和校验逻辑集中在 `sleepSessionViewModel`。
- 目标测试通过，证明用户可见行为没有漂移。

## 检查清单

- 已抽取动作 hook。
- 已抽取最近配置列表组件。
- 已抽取纯 helper。
- 已保持既有 CSS 文件作为睡眠 feature 的样式边界。
- 已补充禁用态样式。
- 已运行目标 TypeScript 和相关 Vitest。
