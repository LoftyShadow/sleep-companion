# 系统 TTS 听书设计

## 目标

在现有睡眠声音应用中增加第一版听书能力。用户可以导入本地文本书稿，选择系统可用音色，把文本切成稳定片段后连续朗读。第一版优先跑通本机系统 TTS 闭环，并为后续云端高质量 TTS、音频缓存和批量生成预留抽象。

## 第一版范围

第一版包含：

- 导入 `.txt`、`.md`、`.markdown` 文本文件。
- 导入非加密 `.epub` 电子书，并按 EPUB spine 章节顺序抽取可朗读文本。
- 在 Web、Linux 桌面和 Windows 桌面等支持拖放的平台，允许把书稿文件直接拖入导入区域，拖入后复用同一套导入校验和解析流程。
- 支持在界面中直接粘贴或编辑文本。
- 自动按段落和句子切分朗读片段。
- Web 和非 Linux、非 Android 桌面优先使用浏览器或 WebView 暴露的系统 `speechSynthesis` 能力朗读。
- Linux 桌面端使用 Tauri 原生命令桥接 `speech-dispatcher` 的 `spd-say`，规避 WebKitGTK `speechSynthesis` 表面可用但实际不稳定的问题。
- Android Tauri 端使用移动端插件桥接系统 `TextToSpeech`，规避 Android WebView 不稳定暴露 `speechSynthesis` 的问题。
- 枚举系统可用音色，允许用户选择音色。
- 支持语速调节。
- 支持播放、暂停、继续、停止、上一段、下一段。
- 显示当前片段、高亮片段列表和播放进度。
- EPUB 书稿按章节聚合片段，界面显示当前播放章节，并支持章节选择、上一章和下一章。
- 显示系统 TTS 不可用或无文本时的错误提示。
- 通过 `TtsEnginePort` 抽象隔离 UI 和 TTS 引擎。

第一版不包含：

- `PDF`、扫描件 OCR 或 DRM 内容解析。
- 完整 EPUB 阅读器能力，例如排版渲染、图片、CSS、脚本、注释、目录跳转、CFI 进度和书架管理。
- 云端 TTS 接入。
- 音频文件生成、下载或缓存。
- 整本书批量转音频。
- 角色识别、多角色配音或对话自动分配音色。
- 后台播放、锁屏控制。
- 书架、阅读进度跨设备同步或账号体系。

## 架构

听书能力拆成三个边界：

```text
文本输入或 EPUB 导入
  -> parsePlainTextBook / parseEpubBook / segmentBookText
  -> useAudiobookPlayer
  -> TtsEnginePort
  -> SystemSpeechSynthesisTtsEngine / LinuxNativeTtsEngine / AndroidNativeTtsEngine
```

### 文本输入

纯文本文件按原有方式处理：文件名用于生成书名，文件正文进入分段器。界面中的文本编辑区也复用同一套分段逻辑，便于快速调试和后续扩展。

EPUB 文件按电子书容器处理：

- 使用 ZIP 条目读取器打开 EPUB，不调用 `file.text()`，也不把整本书拼接成一个巨大字符串。
- 先读取 `META-INF/container.xml` 找到 OPF package 文档。
- 再读取 OPF 的 `manifest` 和 `spine`，只处理 spine 中可线性阅读的 XHTML/HTML 文档。
- 逐个 spine 文档读取、解析、抽取正文文本，并立即复用 `segmentBookText` 生成朗读片段。
- UI 只接收分段后的片段列表，不展示整本 EPUB 正文编辑框。
- UI 基于片段携带的 `sourceHref` 和 `chapterTitle` 生成章节列表；默认只展示当前章节内的片段，避免一次性把整本书的所有片段铺开。
- EPUB 内脚本不执行；导入只通过 `DOMParser` 读取文本内容，并忽略 `script`、`style`、`nav` 等不适合朗读的节点。

这个方案参考 `/home/niemingzhi/RustroverProjects/readest` 中 Foliate 的 EPUB 装载边界：EPUB 作为 ZIP 容器，通过 loader 按路径读取条目，再根据 package/spine 加载章节。当前项目只吸收容器读取和 spine 顺序两个轻量点，不引入完整阅读器。

### 文本分段

分段器输出 `AudiobookSegment`：

```ts
interface AudiobookSegment {
  id: string;
  order: number;
  text: string;
  chapterTitle?: string;
  sourceHref?: string;
}
```

分段规则：

- 先按连续空行切自然段。
- 单段超过目标长度时优先使用 `Intl.Segmenter` 做句级切分，兼顾中文、英文和常见缩写。
- 运行环境没有 `Intl.Segmenter` 时，按中文和英文句末标点继续切分。
- 片段继续过长时按固定字符数兜底切分。
- 空白字符归一化，避免朗读异常停顿。
- EPUB 片段可以携带 `chapterTitle` 和 `sourceHref`，用于界面展示来源和后续扩展进度定位。

第一版不保存 CFI、blockId 或目录树结构；EPUB 只保留朗读所需的顺序片段和轻量章节来源。

### TTS 引擎抽象

UI 和播放 hook 只依赖 `TtsEnginePort`：

```ts
interface TtsEnginePort {
  readonly engineId: string;
  readonly label: string;
  readonly supportsPause: boolean;
  listVoices(): Promise<TtsVoice[]>;
  speak(input: TtsSpeakInput): Promise<TtsPlaybackHandle>;
  cancel(): void;
  destroy(): void;
}
```

系统 TTS 引擎包含三个第一版实现：

- `SystemSpeechSynthesisTtsEngine`：用于 Web、Windows 桌面和其它可用 Web Speech 的运行环境，内部使用 `window.speechSynthesis` 和 `SpeechSynthesisUtterance`。
- `LinuxNativeTtsEngine`：用于 Linux Tauri 桌面端，前端仍实现 `TtsEnginePort`，底层通过 Tauri 应用级 commands 调用 Rust，再由 Rust 执行 `spd-say`。
- `AndroidNativeTtsEngine`：用于 Android Tauri 端，前端仍实现 `TtsEnginePort`，底层通过 Tauri 移动端插件调用 Kotlin，再由 Kotlin 使用系统 `TextToSpeech`。

后续云 TTS 可以实现同一个端口，但返回的 `TtsPlaybackHandle` 内部改为播放生成后的音频。

### 与声音调音台并存

听书和声音调音台是两个可以同时播放的功能域：

- 声音调音台继续通过 `PlayerPort` 控制白噪音、ASMR 和自定义音频。
- 听书继续通过 `TtsEnginePort` 控制系统 TTS。
- 顶层应用只负责模式导航和可见性切换，不在切换到听书时停止声音，也不在切回声音时停止 TTS。
- 声音调音台随应用常驻挂载；听书在用户首次进入后挂载并保持挂载，避免切换模式时销毁 hook 状态或释放正在播放的任务。
- 用户需要停止其中一类声音时，必须使用对应功能区自己的停止按钮。

这种边界避免把 TTS 强行塞进白噪音混音器，也避免顶层模式切换产生隐式副作用。后续如果需要全局“全部停止”，应新增显式全局控制，而不是复用模式切换行为。

### 播放状态

`useAudiobookPlayer` 维护：

- 当前片段索引。
- 章节列表、当前章节索引和当前章节信息。
- 播放状态：`idle`、`loading`、`playing`、`paused`、`ended`、`error`。
- 当前音色、语速和错误信息。
- 片段列表和总进度。

当一段朗读结束后，如果还有下一段，自动朗读下一段；到最后一段后进入 `ended`。每次朗读片段前根据当前片段文本做轻量语言判断：简体中文作为默认兜底，纯英文片段使用 `en-US`，日文和韩文按脚本使用对应语言；如果系统没有匹配音色，则不强绑错误音色，让系统 TTS 按 `lang` 自行路由。

章节导航只改变当前片段索引并从目标章节第一段开始朗读，不改变底层连续播放规则。自动连播跨过章节边界时，当前章节由当前片段反推并自动更新。

## 平台策略

第一版按平台选择系统 TTS：

- Web 和 Windows 桌面优先走 WebView 或浏览器 `speechSynthesis`。
- Linux 桌面端走 Tauri 原生 command。原因是本机验证显示 WebKitGTK 暴露了 `speechSynthesis`，但中文朗读在 Tauri Linux 场景下不可稳定出声；同一机器上 `spd-say` 可以直接出声。
- Android Tauri 端走 Tauri 移动端插件和 Kotlin 原生 `TextToSpeech`。原因是 Android WebView 不保证稳定暴露 `speechSynthesis`，直接依赖 Web Speech 会导致听书播放不可用。

Android TTS 适配器实现同一个 `TtsEnginePort`，UI 不直接依赖 Kotlin。

### Linux 原生 TTS

Linux 第一版依赖系统 `speech-dispatcher`：

- `listVoices` 返回 Speech Dispatcher 的常见 voice type，包括男声、女声和童声类型。
- `speak` 使用 `spd-say -w`，让前端可以在命令结束后触发下一段朗读。
- `cancel` 使用 `spd-say -S` 停止当前朗读，避免影响系统中其它 Speech Dispatcher 队列。
- 前端只在已有原生朗读任务时调用 `cancel`，避免页面初始化、文本重算或播放前预取消反复触发 Speech Dispatcher autospawn。
- `language` 根据片段文本轻量判断后传给 `spd-say -l`，中文默认映射为 `zh`。
- 语速、音高和音量映射到 `spd-say` 的 `-r`、`-p`、`-i` 参数。
- Tauri 命令使用 `native_tts_list_voices`、`native_tts_speak` 和 `native_tts_cancel`，避免内联自定义插件还需要额外维护 plugin ACL。

`spd-say` 不提供与 Web Speech 等价的暂停和继续能力，因此 Linux 原生引擎声明 `supportsPause = false`。UI 在该引擎下把主按钮从“暂停”切换为“停止”，避免展示不可用的交互。

### Android 原生 TTS

Android 第一版依赖系统 `TextToSpeech`：

- `listVoices` 返回系统 TTS 引擎暴露的 `Voice` 列表，包含名称、语言、本地或联网需求以及默认音色标记。
- `speak` 使用 `TextToSpeech.speak` 和 `UtteranceProgressListener`，等系统回调完成后再让前端推进到下一段。
- `cancel` 调用 `TextToSpeech.stop()` 并结束当前 pending 调用，避免前端播放流程挂起。
- `language` 按片段语言传给系统 TTS；如果系统不支持目标语言，则回退到设备默认语言。
- 语速、音高和音量映射到 `setSpeechRate`、`setPitch` 和 `KEY_PARAM_VOLUME`。
- Tauri 插件使用 `plugin:native-tts|listVoices`、`plugin:native-tts|speak` 和 `plugin:native-tts|cancel`，并通过 capability 授权。

Android `TextToSpeech` 不提供真正的暂停和继续能力，因此 Android 原生引擎声明 `supportsPause = false`。UI 在该引擎下使用停止语义，避免伪装不可恢复的暂停。

## 参考项目取舍

参考 `/home/niemingzhi/RustroverProjects/readest` 后，第一版借鉴这些方向：

- TTS 客户端抽象，不让 UI 直接依赖具体引擎。
- Web Speech 使用句级粒度，避免一整章一次性朗读。
- EPUB 使用 ZIP loader 和 OPF spine 顺序读取章节，避免把整本 EPUB 当作普通文本一次性加载。
- Android 原生 TTS 通过 Tauri 插件实现同一端口，后续仍可在端口后替换为前台服务或 Media3/ExoPlayer 方案。

第一版不复制 `readest` 的完整 Foliate 阅读器、SSML mark、高亮 range、Edge TTS、媒体通知和前台服务架构。这些能力适合正式电子书阅读器，但当前项目先做轻量听书入口。

## UI 设计

新增顶层模式：

- `声音`：保留现有白噪音和 ASMR 调音台。
- `听书`：显示文本导入、音色控制和分段朗读。

顶层模式是界面可见性切换，不代表播放互斥。用户可以先播放白噪音或 ASMR，再进入听书开始朗读；也可以在听书播放中切回声音调音台继续调整环境声。

听书界面包含：

- 左侧控制区：导入书稿、音色选择、语速、播放控制、当前状态。
- 右侧文本区：文本编辑框或 EPUB 来源状态、当前章节导航和当前章节分段滚动列表。
- 当前片段高亮并在朗读推进时保持可见，便于确认朗读位置。

导入区域同时支持点击选择文件和拖入文件。拖入文件只作为桌面和 Web 端的快捷入口，不替代移动端文件选择；拖入多个文件时第一版只处理第一个文件，避免批量导入引入播放顺序和错误汇总复杂度。

EPUB 章节名称只在章节导航、章节选择器和章节摘要中展示；当前章节内的每个朗读片段不再重复显示章节名称，避免长章节列表里出现大量重复标签。

导入纯文本时保留文本编辑框；导入 EPUB 时右侧只展示来源状态、章节选择和当前章节内的有限高度分段列表，不把 EPUB 全文回填到编辑框，也不一次性把列表撑满页面。

分段列表允许用户自行滚动。`currentSegmentIndex` 变化时，界面自动把当前朗读片段滚动到可见范围内，但不在章节刚开始时强制把第一段放到列表中心。用户停止滚动 2 秒后，列表自动回到当前朗读片段；列表下方也提供“定位到当前正在阅读”按钮，用户手动滚开后可以一键回到当前朗读片段。

片段列表不使用省略号隐藏正文。普通长度的片段完整显示；过长正文应在分段阶段拆成更短的朗读片段，默认目标长度约 120 字，单片段硬上限约 180 字。

界面不加入长篇说明文字，只保留必要状态、按钮和错误提示。

## 云 TTS 预留

后续云 TTS 不直接改 UI，而是新增端口实现：

```text
CloudTtsEngine
  -> synthesize(text, voiceId, rate)
  -> audio blob 或本地文件
  -> HTMLAudio 播放
```

需要新增但本次不实现：

- 云端音色列表。
- 用户 API key 或后端代理。
- 分段音频缓存。
- 预生成下一段。
- 缓存空间清理。
- 上传文本的隐私提示。

## 错误处理

- 当前 Web Speech 运行环境没有 `speechSynthesis` 时，禁用播放并显示“当前环境不支持系统 TTS”；Android Tauri 端不依赖 WebView `speechSynthesis`。
- 没有可朗读文本时，播放按钮不启动朗读。
- EPUB 缺少 `container.xml`、OPF、spine 或可朗读正文时，导入失败并显示明确错误。
- 加密或 DRM EPUB 暂不支持，导入时显示不支持提示。
- 系统 TTS 触发错误时进入 `error` 状态，并保留当前片段位置。
- Linux 桌面缺少 `speech-dispatcher` 或 `spd-say` 时，显示 Linux 系统 TTS 依赖缺失错误。
- Android 系统 TTS 初始化失败、缺少目标音色或朗读回调出错时，显示 Android 系统 TTS 错误。
- 切换文本、音色或语速时停止当前朗读，避免旧朗读任务继续播放。

## 验收标准

- 系统 TTS 抽象可以枚举音色并朗读指定文本。
- 文本分段器能处理普通段落、长句和空文本。
- EPUB 导入器能按 OPF spine 顺序读取 XHTML 章节，并直接输出顺序朗读片段。
- EPUB 导入不能把整本书拼接成一个完整正文传给文本编辑框。
- EPUB 听书界面能显示当前章节，支持选择章节、上一章和下一章，并且当前章节片段列表限制高度、支持滚动。
- EPUB 当前章节内的片段列表不重复显示每个片段所属的章节名。
- 当前朗读片段必须在播放推进时自动滚动到可见范围内，并提供手动定位按钮。
- 听书 hook 能播放、暂停、继续、停止、切换上一段和下一段。
- UI 可以导入文本文件或 EPUB、选择音色、调节语速并显示片段列表。
- UI 可以通过拖入文件导入文本文件或 EPUB，拖入和点击选择必须使用相同的文件校验、错误提示和导入结果展示。
- 现有声音调音台功能继续可用。
- 声音调音台和听书可以同时播放，模式切换不能隐式调用 `PlayerPort.stopAll()` 或 `TtsEnginePort.cancel()`。
- 切换模式后再切回，正在播放的声音状态和听书状态必须保留。
- 必须通过：

```bash
pnpm run check
```

Android 真机系统 TTS 可用性需要实际设备验证。除非实际运行过，不得声称 Android 真机听书验证通过。
