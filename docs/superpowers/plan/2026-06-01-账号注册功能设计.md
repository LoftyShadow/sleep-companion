# 账号注册功能设计

## 背景

本设计在邮箱密码登录接口和前端“我的”页登录入口基础上，补齐邮箱密码注册能力。注册入口让用户可以从产品内创建 `app_users` 与 `password_credentials` 记录，不再依赖外部手工写库。

## 目标

- 新增 `POST /api/auth/register`。
- 注册成功后直接返回与登录一致的认证结果：`accessToken`、`refreshToken` 和 `user`。
- 前端“我的”页支持在登录和注册之间切换。
- 保持现有 `POST /api/auth/login` 响应结构不变。

## 非目标

- 不实现邮箱验证码发送或邮箱验证状态变更。
- 不实现 refresh token 轮换、退出登录或会话恢复。
- 不新增用户名、头像、第三方登录或邀请码。
- 不新增业务表；会调整 `app_users.email` 的唯一约束，使唯一性只约束有效用户。

## 后端接口

```text
POST /api/auth/register
```

请求体：

```json
{
  "email": "user@example.com",
  "password": "secret123",
  "displayName": "梦伴用户"
}
```

字段规则：

- `email` 会 `trim` 并转为小写后保存。
- `password` 长度必须不小于 `auth.password_min_length`。
- `displayName` 可选，空白字符串按未设置处理。

成功响应沿用登录响应结构：

```json
{
  "code": "ok",
  "message": "ok",
  "data": {
    "accessToken": "jwt",
    "accessTokenExpiresInSeconds": 900,
    "refreshToken": "refresh-token",
    "user": {
      "id": "739182738912312320",
      "email": "user@example.com",
      "displayName": "梦伴用户"
    }
  },
  "requestId": "req_xxx"
}
```

错误码：

- `auth.invalid_register_request`：邮箱为空或密码长度不足。
- `auth.email_already_registered`：邮箱已存在且账号仍处于有效状态。
- `auth.token_issue`：注册成功后的 token 签发失败。
- `database_unavailable`：数据库不可用。

## 后端流程

1. 解析 JSON 请求体，失败返回 `auth.invalid_request`。
2. 规范化邮箱和展示名。
3. 校验邮箱非空、密码长度。
4. 查询未软删除的 `app_users.email`。
5. 存在有效用户时返回 `auth.email_already_registered`。
6. 只存在软删除历史用户时，不恢复旧记录，创建新的 `app_users` 和新的 `password_credentials`。
7. 使用 `Argon2id` 哈希密码，数据库只保存密码哈希。
8. 复用登录的 access token、refresh token 和 `refresh_sessions` 创建逻辑。

## 数据库约束

旧版 `app_users.email` 全表唯一约束会阻止“保留软删除历史记录，同时允许同邮箱重新注册”。注册能力通过 migration 调整为：

- 移除旧的 `app_users_email_key` 全表唯一约束。
- 新增 `app_users_active_email_unique_idx`，只约束 `deleted_at is null` 的有效用户邮箱唯一。

这样软删除历史记录保留不变，同邮箱重新注册会生成新的用户行；同一时间仍只能存在一个有效用户占用该邮箱。

第一版不引入注册限流。登录限流继续只保护登录失败路径。

## 前端交互

`AccountView` 维持同一个账号面板，新增登录和注册模式切换：

- 登录模式显示邮箱、密码和“登录”按钮。
- 注册模式显示邮箱、密码、昵称和“注册并登录”按钮。
- 注册成功后进入已登录展示。
- 后端错误消息直接展示在表单上方。

## Component Map

Page / Route：`AppWorkspace` 继续负责挂载 `AccountView`。

Feature Component：`AccountView` 负责登录/注册模式、表单状态、提交状态、错误状态和已登录展示。

API Adapter：`authApi.ts` 负责 `loginWithPassword`、`registerWithPassword`、base URL 解析、envelope 解析和错误封装。

Style File：`AccountView.css` 继续只承载账号页样式。

## 验收标准

- `POST /api/auth/register` 注册新邮箱时返回 token 和用户信息。
- 已软删除邮箱重新注册时创建新的用户行。
- 有效用户重复邮箱注册返回 `auth.email_already_registered`。
- 注册密码低于最小长度时返回 `auth.invalid_register_request`。
- 前端注册表单会调用 `/api/auth/register` 并在成功后显示已登录状态。
- `pnpm run check` 通过。
