# 自定义音频播放实现计划

## 目标

在现有声音库中增加自定义音频导入、持久化、播放和删除能力。第一版以最小可用为目标，不引入云同步、转码或自定义预设。

## 执行步骤

- [x] 更新声音模型，区分内置声音和自定义声音。
- [x] 添加自定义音频存储模块，使用 IndexedDB 保存 Blob。
- [x] 添加自定义音频 React hook，负责加载、导入、删除和对象 URL 生命周期。
- [x] 添加 Android 组合播放器，让 Android 内置声音继续走原生，自定义音频走 Web 音频。
- [x] 调整 `useSoundMixer`，支持运行时追加的动态声音 ID。
- [x] 调整 UI，在声音库顶部增加添加入口，并在自定义声音卡片上显示移除操作。
- [x] 补充 Vitest 测试，覆盖存储工具、组合播放器和 UI 入口。
- [x] 运行完整门禁。

## 关键约束

- UI 继续只依赖 `PlayerPort`，不能直接判断底层播放器实现。
- 自定义音频不加入内置预设。
- 自定义音频不写入 Android raw 资源。
- 不新增 Tauri 文件系统插件。
- 不实现转码或后台播放。
- 文档和代码必须保持中文业务说明。

## 剩余风险

- 不同浏览器或 WebView 对具体音频格式支持不同，第一版只做导入格式过滤，不做转码。
- IndexedDB 存储容量受平台策略影响，大文件或大量音频可能写入失败。
- Android 自定义音频使用 WebView 音频能力，切后台表现不保证。

## 优化修复记录

- 批量导入自定义音频时，成功导入的文件会立即进入 UI，失败文件会单独汇总提示，避免数据库和界面状态不一致。
- IndexedDB 读取、保存和删除都等事务完成后再确认成功，避免请求成功但事务最终失败的误判。
- Android 混合播放器按 `custom:` 声音 ID 路由自定义音频音量和暂停操作，避免播放前调音量误发给原生播放器。
- Web 音频暂停单个声音时同步释放 `src`、`load()` 并清理音量缓存，避免暂停后的临时资源长期保留。
