# B站听视频实现计划

## 目标

新增“听视频”模式，第一版只支持 B 站官方播放器嵌入。用户粘贴 B 站链接后，应用解析 `BV`、`av`、`ep` 或直播房间号，并按来源类型载入对应官方播放器。

本轮补充体验细节：点击“载入”后通过 `autoplay=1` 尝试自动播放，并在链接输入区提供“粘贴”按钮读取系统剪贴板文本。

本轮追加直播支持：普通视频和番剧继续使用 `player.bilibili.com/player.html`；直播间链接使用 `www.bilibili.com/blackboard/live/live-activity-player.html?cid=房间号`。解析结果通过枚举区分视频和直播，再由策略工厂生成统一 iframe source。

本轮追加收听面板外观：右侧主视觉改成类似音乐播放器的当前来源卡片，官方 iframe 缩小为播放源区域。该改动只改变 UI 外观，不抓取真实媒体流，不自建播放控制。

本轮追加外层收听控制：直播播放器通过官方 `postMessage` 支持外层播放/暂停和音量控制；普通视频外链没有公开外部控制接口，暂停通过卸载播放源停止声音，音量仍需在官方播放源内调整。

## 关键约束

- 只使用 B 站官方视频外链播放器和官方直播活动播放器。
- 不抓取真实音视频流，不下载、不缓存、不转码。
- 不隐藏官方播放器后只播放音频。
- 不绕过 B 站登录、会员、地区、版权、广告或其它限制。
- 自动播放只通过官方播放器参数尝试，不做浏览器策略绕过。
- 链接解析只做本地字符串处理，不请求 B 站非公开接口；不联网跟随短链接。
- 听视频模式切换只改变可见性，不主动停止 `PlayerPort` 或 `TtsEnginePort`。
- 文档正文保持中文。

## 验收命令

先运行聚焦测试：

```bash
rtk pnpm vitest run src/features/videoListening src/features/appMode
```

最后运行完整门禁：

```bash
rtk pnpm run check
rtk git diff --check
```

## 剩余风险

- B 站官方播放器对部分视频可能要求登录、会员、地区或版权条件，应用不做绕过。
- 桌面 WebView 对第三方 iframe 的策略可能与浏览器不同，需要按实际平台验证。
- `b23.tv` 短链接如果不包含可解析路径，第一版不会联网跟随跳转，因此无法识别。
