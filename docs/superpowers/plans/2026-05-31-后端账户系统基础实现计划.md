# 后端账户系统基础实现计划

## 范围

本阶段只搭建后端基础设施，不实现完整账户业务流程。

## 步骤

1. 新增根 `Cargo.toml`，把 `backend` 和 `src-tauri` 设为 workspace member。
2. 新增 `backend/` crate，目标采用 `Axum + SeaORM + PostgreSQL`。
3. 引入 `config` crate，使用分层 TOML 配置和环境变量覆盖。
4. 新增 `GET /healthz` 和 `GET /readyz`。
5. 新增账户系统基础 migration。
6. 在设计中固化短期 access JWT 加数据库持久化 opaque refresh token 策略。
7. 预留 `MailSender` 抽象和不发送邮件的 `NoopMailSender`。
8. 固化统一 API 响应 envelope，并让健康检查接口使用该结构。
9. 固化 Snowflake 风格 `bigint` ID、逻辑外键和通用字段约定。
10. 固化 `tracing + tracing-subscriber + tower-http TraceLayer` 日志方案，开发环境写本地日志文件，生产环境输出 JSON stdout。
11. 固化 `tokio-cron-scheduler` 定时任务方案，限定为轻量维护任务。
12. 固化 `utoipa + utoipa-swagger-ui` 接口文档方案，开发环境开启，生产默认关闭。
13. 固化第一版 CORS 全放开、登录组合限流、密码最小 6 位、Docker Compose 部署但不内置 PG、AI 暂不纳入第一版。
14. 调整 `package.json` 的 Rust 检查脚本，使其覆盖整个 workspace。
15. 运行格式化、Rust 检查和仓库质量门禁。

已完成内容：

5. 移除 SQLx 运行时依赖和旧 SQLx migration 文件。
6. 增加开发日志文件输出、`x-request-id` header 和健康检查成功响应 envelope 的真实 `requestId` 注入。
7. 引入 `tokio-cron-scheduler`，先注册轻量维护任务预留逻辑，并通过配置开关控制。

9. 引入 CORS layer，第一版允许任意来源。
10. 补 Docker Compose 后端服务部署文件，但不把 PostgreSQL 放入 Compose。

未在本轮实现的业务能力：

1. 注册、登录、refresh token 和退出登录接口。
2. 登录组合限流的业务扣数逻辑。
3. 密码哈希、access JWT 签发和 refresh session 轮换。
4. 忘记密码与重置密码。
5. 错误响应路径中的 request id 全链路注入和 tracing span 字段统一。

## 数据库迁移约定

SeaORM 切换完成后，数据库版本管理使用 `sea-orm-migration`。本地开发可以手动执行 migration，生产环境必须由部署流程在后端服务启动前执行 migration，不在每个后端实例启动时自动执行。

生产发布顺序：

1. 构建后端服务和 migration 可执行目标。
2. 备份数据库或确认托管平台可恢复。
3. 执行 `cargo run -p backend-migration -- up` 或等价部署命令。
4. migration 成功后启动或滚动更新后端服务。
5. 发布后检查 `/readyz` 和应用日志。

## 定时任务约定

第一版只使用进程内 scheduler 处理轻量维护任务。生产多实例部署时，同一类定时任务只能在一个实例启用；如果未来需要多个实例共同运行，需要先补 PostgreSQL advisory lock 或 job table 抢占机制。

AI 故事和 AI ASMR 生成不进入 cron。它们必须通过后台任务模型处理，至少包含任务状态、失败重试、成本记录和用户额度扣减。

第一版暂不实现 AI 故事和 AI ASMR，因此不需要创建 AI 生成任务表和 worker。

## Auth 第一版约定

第一版账户能力只围绕邮箱密码登录展开：

- 密码最小长度为 6 位。
- 暂不实现邮箱验证。
- 暂不实现第三方 OAuth。
- 暂不实现手机号登录。
- 登录接口必须做组合限流。
- 登录失败响应不得泄露邮箱是否存在。

## 部署约定

第一版后端按 Docker Compose 部署，但 PostgreSQL 不写入 Compose 服务。部署时通过配置或环境变量传入外部 PostgreSQL 的连接串。

后端服务本身优先使用结构化数据库配置：

```toml
[database]
host = "localhost"
port = 5432
database = "sleep_companion_dev"
username = "postgres"
password = "postgres"
ssl_mode = "disable"
```

如果 `database.url` 存在且非空，则优先使用完整连接串，便于云平台和 Docker Compose 注入：

```toml
[database]
url = "postgres://postgres:postgres@localhost:5432/sleep_companion_dev"
```

Compose 中的 `APP_DATABASE__URL`、`APP_AUTH__JWT_SECRET` 和 `APP_ID_GENERATOR__WORKER_ID` 是对 TOML 分层配置的环境变量覆盖，不替代 TOML 配置体系。非敏感默认值继续放在 `backend/config/*.toml`，生产敏感项通过环境变量或部署平台 secret 注入。

`backend-migration` 使用 SeaORM migration CLI，仍通过标准 `DATABASE_URL` 环境变量接收连接串。

Compose 只负责后端服务本身；migration 仍作为部署前置步骤执行。

## 接口文档约定

后端接口文档使用 `utoipa + utoipa-swagger-ui`。开发环境暴露 `/api-docs/openapi.json` 和 `/swagger-ui`，生产环境默认关闭 Swagger UI。

实现 Auth 接口时必须同步补充 OpenAPI 注解，至少覆盖：

- 请求体 DTO。
- 成功响应 envelope。
- 错误响应 envelope。
- 业务错误码。
- 鉴权要求。

## 破坏性更新说明

引入根 Rust workspace 后，Rust 依赖锁文件将从 `src-tauri/Cargo.lock` 迁移到根目录 `Cargo.lock`。后续 Rust 检查应从仓库根目录执行：

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

兼容策略：

- `src-tauri` 继续作为 workspace member 保留原 crate 名称和 Tauri 配置。
- `package.json` 中的 Rust 脚本改为 workspace 级命令。
- Tauri 相关源码不做业务行为改动。

回滚方式：

- 删除根 `Cargo.toml` 和 `backend/`。
- 恢复 `src-tauri/Cargo.lock`。
- 把 `package.json` 的 Rust 脚本恢复为 `cd src-tauri && cargo ...`。
