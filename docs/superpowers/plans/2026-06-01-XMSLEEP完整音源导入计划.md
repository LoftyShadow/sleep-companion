# XMSLEEP 完整音源导入计划

## 步骤 1：资源导入

目标：把 XMSLEEP `sounds_remote.json` 中的完整音源复制进本项目。

涉及文件：

- `public/audio/xmsleep/**`
- `src-tauri/gen/android/app/src/main/res/raw/xmsleep_*.ogg`
- `public/images/sounds/xmsleep/*.webp`

验收：

- 清单中每个声音都有 Web 音频、Android 音频和图片。
- 已存在于 XMSLEEP 的同名图片优先复用。
- XMSLEEP 没有图片的声音生成波形图。

## 步骤 2：声音清单接入

目标：把完整 XMSLEEP 音源作为内置集合接入前端，生成“其他声音”使用的去重补充集合，并把“咖啡厅”归入“白噪音”。

涉及文件：

- `src/features/sounds/soundCatalog.ts`
- `src/features/sounds/xmsleepSoundCatalog.ts`
- `src/features/sounds/soundCatalog.test.ts`

验收：

- `BUILT_IN_SOUNDS` 包含白噪音、ASMR 和 XMSLEEP 完整音源。
- `XMSLEEP_WHITE_NOISE_SOUNDS` 包含用户指定归入白噪音的“咖啡厅”。
- `XMSLEEP_OTHER_SOUNDS` 只包含现有白噪音和 ASMR 没有覆盖的 XMSLEEP 声音。
- 测试能校验“其他声音”没有包含已覆盖的 XMSLEEP 来源音频和“咖啡厅”。
- 测试能校验所有 XMSLEEP 条目的资源文件存在。
- 预设引用仍只指向有效内置声音。

## 步骤 3：声音库 UI 接入

目标：新增“其他声音”顶层页签，展示去重后的 XMSLEEP 补充音源和分类筛选。

涉及文件：

- `src/features/mixer/SoundMixerView.tsx`
- `src/features/mixer/soundLibraryModes.ts`
- `src/features/mixer/MixerHeader.css`
- `src/features/mixer/SoundLibrarySidebar.tsx`
- `src/features/mixer/SoundLibrarySidebar.css`
- `src/features/mixer/SoundCategoryFilter.tsx`
- `src/features/mixer/SoundCategoryFilter.css`
- `src/features/appMode/AppWorkspace.integration.test.tsx`

验收：

- 顶部声音模式显示“白噪音”、“ASMR”和“其他声音”。
- 白噪音显示原有声音、XMSLEEP 咖啡厅和原有预设。
- ASMR 继续只显示原有声音和预设。
- “其他声音”能看到去重后的 XMSLEEP 补充音源和分类筛选。
- 点击分类后只显示该分类下的补充音源和自定义音频。
- “其他声音”统一播放按钮能启动当前分类前 3 个补充声音。

## 步骤 4：自定义音频上传区调整

目标：满足“按钮放到最右面，选文件即上传的话放在按钮的左面”的布局要求。

涉及文件：

- `src/features/mixer/CustomAudioPanel.tsx`
- `src/features/mixer/CustomAudioPanel.css`

验收：

- 上传按钮位于面板最右侧。
- “选文件后自动导入”的提示位于按钮左侧。
- 小屏幕下布局不溢出。
