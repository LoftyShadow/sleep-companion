# 后端登录接口实现计划

## 范围

本轮实现后端邮箱密码登录接口，与前端“我的”tab 的登录契约对齐。

## 步骤

1. 新增后端登录接口设计文档，明确接口、token、限流和非目标。
2. 引入登录所需依赖：
   - `argon2`
   - `jsonwebtoken`
   - `rand`
   - `sha2`
   - `base64`
3. 新增 `backend/src/auth.rs`，实现：
   - 请求和响应 DTO。
   - Argon2id 密码校验。
   - access JWT 签发。
   - opaque refresh token 生成与 hash。
   - `refresh_sessions` 写入。
   - 登录组合限流检查与失败扣数。
4. 调整 `AppState`，加入 auth 配置、登录限流配置和 ID 生成器。
5. 在 `build_router` 中挂载 `POST /api/auth/login`。
6. 更新 OpenAPI 文档声明。
7. 补充单元测试和路由测试。
8. 运行 `rtk pnpm run check`。

## 验收标准

- `POST /api/auth/login` 路由存在。
- 邮箱或密码错误返回 `auth.invalid_credentials`。
- 限流命中返回 `auth.rate_limited`。
- 成功登录返回 `accessToken`、`accessTokenExpiresInSeconds`、`refreshToken` 和 `user`。
- refresh session 只保存 token hash，不保存 refresh token 原文。
- OpenAPI schema 包含登录请求和响应。
- `rtk pnpm run check` 通过。

## 破坏性更新说明

本轮无数据库 schema 破坏性更新。`build_router` 的函数签名会增加运行时配置和 ID 生成器参数，但这是后端内部 API 调整，不影响前端和外部 HTTP 接口。
