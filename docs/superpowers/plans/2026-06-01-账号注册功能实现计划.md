# 账号注册功能实现计划

## 范围

本轮新增邮箱密码注册能力，并把注册入口接到现有账号页。注册成功后直接登录，返回与登录一致的认证结果。

## 涉及文件

- `backend/src/auth.rs`
- `backend/src/app.rs`
- `backend/src/error.rs`
- `backend/src/openapi.rs`
- `backend-migration/src/lib.rs`
- `backend-migration/src/m20260601_213000_allow_reregister_deleted_email.rs`
- `src/features/account/authApi.ts`
- `src/features/account/authApi.test.ts`
- `src/features/account/AccountView.tsx`
- `src/features/account/AccountView.test.tsx`
- `src/features/account/AccountView.css`

## 步骤

1. 后端注册契约
   - 新增 `RegisterRequest`。
   - 新增注册错误分支。
   - 有效邮箱冲突时返回稳定错误；软删除账号重新注册时创建新的用户和凭证记录。
   - 抽取登录和注册共用的 token/session 响应创建逻辑。

2. 数据库约束
   - 新增 migration，移除 `app_users.email` 全表唯一约束。
   - 新增 `deleted_at is null` 的有效用户邮箱唯一索引。

3. 后端路由与测试
   - 在 router 挂载 `POST /api/auth/register`。
   - OpenAPI 纳入注册接口和 schema。
   - 增加注册成功、重复邮箱、无效请求测试。

4. 前端 API 适配
   - 新增 `registerWithPassword`。
   - 保持登录 API 行为不变。
   - 增加注册请求路径和错误传播测试。

5. 前端账号页
   - 增加登录/注册模式切换。
   - 注册模式增加昵称输入。
   - 注册成功后复用已登录展示。
   - 增加注册表单测试。

6. 验证
   - 先运行目标测试定位问题。
   - 最后运行 `pnpm run check`。

## 风险与约束

- 不新增注册限流，避免引入当前需求之外的表结构或策略；后续需要防滥用时再单独设计。
- 不做邮箱验证码，`email_verified_at` 保持 `None`。
- 旧登录接口不改路径、不改响应字段，避免影响已接入前端。

## 验收清单

- [ ] 注册接口能创建用户和密码凭证。
- [ ] 注册成功返回 access token、refresh token 和用户信息。
- [ ] 有效用户重复注册时有稳定错误码，软删除用户重新注册时创建新用户记录。
- [ ] 前端能在账号页切换到注册并提交。
- [ ] `pnpm run check` 通过。
