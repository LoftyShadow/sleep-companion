## 破坏性更新说明

本次不改变 API 请求和响应结构，不新增数据库迁移，不改变 `PlayerPort` 接口。

生产环境 CORS 行为会从硬编码宽松收敛为配置驱动。如果生产部署依赖浏览器跨域访问，需要在配置中设置真实允许来源；这是安全边界收敛，不是业务接口破坏。

## 风险处理

- 如果 upsert SQL 与 SeaORM mock 测试不兼容，保留纯函数测试 SQL 参数，并通过现有接口测试覆盖行为不回退。
- 如果 CORS 生产白名单为空，浏览器跨域调用会被拒绝；部署时必须显式配置。
- 如果 Android WebView 不支持准确配额估算，仍依赖大小上限保护。
- 如果结构拆分导致 React effect 依赖变化，以现有集成测试和类型检查作为第一道保护。
