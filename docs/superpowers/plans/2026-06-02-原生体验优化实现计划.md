# 原生体验优化实现计划

## 步骤

1. 编写原生体验优化设计文档和本实现计划。
2. Android 原生音频生命周期：
   - 在 `NativeAudioPlugin` 中覆盖 `onStop()` 和 `onDestroy(...)`。
   - 调用 `NativeAudioPlayer.stopAll()` 释放全部 `MediaPlayer`。
   - 保持当前 `pause()` 和 `stopAll()` 行为不变。
3. Android 系统 TTS 生命周期：
   - 在 `NativeTtsPlugin` 中覆盖 `onStop()` 和 `onDestroy(...)`。
   - `onStop()` 停止当前朗读并 resolve 当前请求。
   - `onDestroy(...)` 调用 `TextToSpeech.shutdown()`，并清理等待初始化回调和当前请求。
4. 音量 IPC 节流：
   - 在 `useSoundMixer` 内对 `PlayerPort.setVolume` 做按 `soundId` 合并提交。
   - 保留 UI 状态即时更新。
   - 在 `stopAll()`、预设切换和 hook 清理时取消待提交音量。
   - 补充 Vitest 覆盖连续音量变化只提交最终值。
   - 补充 Vitest 覆盖手动音量调整立即清除预设，以及慢速音量提交不会覆盖后续新预设状态。
5. 桌面原生感细节：
   - 桌面 Tauri 环境下取消全局按钮手型光标。
   - 保留 Web 浏览器预览的按钮手型光标。
   - 移除听书段落列表的常驻 `scroll-behavior: smooth`。
6. CSP 收紧：
   - 将 `tauri.conf.json` 的 `app.security.csp` 从 `null` 改为基础白名单策略。
   - 覆盖本地资源、音频、图片、Tauri 协议和必要远程连接。
   - `connect-src` 保留本地账号服务端口，并允许 `https:` 远程账号后端覆盖。
7. 验证：
   - 运行相关前端测试。
   - 运行仓库质量门禁。

## 验收

- Android 插件生命周期代码编译通过。
- Android 进入后台或 Activity 销毁时，原生音频不继续持有播放器。
- Android 进入后台或 Activity 销毁时，TTS 不继续朗读或持有引擎。
- 连续拖动同一个声音音量时，播放器只收到合并后的最终音量。
- 停止全部或应用预设后，不会再提交旧的待处理音量。
- 慢速音量提交完成后，不会清除后续新应用的预设状态。
- 桌面端按钮光标和滚动行为更接近系统默认。
- CSP 不再为空。
- 必须通过：

```bash
rtk pnpm run check
```

## 破坏性更新说明

本次没有接口破坏性更新，但有一个用户可见行为收敛：

- Android 应用离开前台后会停止内置音频和 Android TTS。

这是第一版已确认边界的一部分，不属于后台播放能力回退。未来如果新增后台播放，需要重新设计前台服务、通知控制和生命周期策略。

## 风险

- CSP 收紧后，如果某些远程资源来源遗漏，运行时可能被拦截。验证时需要关注 B 站听视频入口和本地音频资源。
- 生产 CSP 为支持账号远程后端覆盖放行 `connect-src https:`，不额外放开脚本、图片、媒体和 iframe 来源。
- 音量节流如果清理不完整，可能在停止播放后补发旧音量；实现中必须对 `stopAll()`、预设切换和组件卸载做取消处理。
- Android 生命周期释放需要依赖 Tauri Android 插件生命周期触发，真机行为仍需后续手动验证。
