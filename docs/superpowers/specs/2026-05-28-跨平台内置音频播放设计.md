# 跨平台内置音频播放设计

## 目标

为 Sleep Companion 实现第一版内置音频播放能力。第一版必须在 Web、Linux 桌面端、Windows 桌面端和 Android 前台运行时提供一致的基础播放体验。

## 已确认范围

第一版包含：

- 17 个内置声音：
  - `heavy_rain` / 大雨
  - `campfire` / 篝火
  - `forest_birds` / 林中鸟声
  - `thunder` / 雷声
  - `wind` / 风声
  - `clock` / 时钟
  - `keyboard` / 键盘
  - `library` / 图书馆
  - `drifting` / 漂流
  - `heavy_rain_seg_0` / 大雨片段
  - `morning_coffee` / 清晨咖啡
  - `office` / 办公室
  - `rowing` / 划船
  - `snow_walking` / 雪地行走
  - `typewriter` / 打字机
  - `umbrella_rain` / 伞下雨声
  - `windmill` / 风车
- 简单播放 UI。
- 点击声音卡片播放或暂停对应声音。
- 循环播放。
- 多个声音可同时播放。
- 每个声音可单独调音量。
- 统一播放/停止按钮：无声音播放时启动当前预设或上次混音；有声音播放时停止全部声音。
- 内置预设：按场景分组展示，点击预设后一次性应用该预设包含的声音和音量。
- 支持 Web、Linux、Windows 和 Android 第一版能力。
- Android 第一版要求前台真机播放可用，代码结构为未来后台播放预留。
- 在 `package.json` 中提供 Web、Linux、Windows 和 Android 的启动/构建脚本，方便按平台运行。

第一版不包含：

- 远程音频列表。
- 下载缓存。
- 用户导入音频。该项仅表示内置声音第一版不包含导入能力；后续自定义音频播放能力见 `docs/superpowers/specs/2026-05-28-自定义音频播放设计.md`。
- 用户自定义预设。
- 预设置顶或排序。
- 倒计时。
- 最近播放恢复。
- 通知栏控制。
- 锁屏播放。
- 耳机按键。
- 来电暂停和恢复。
- iOS。

## 架构

使用同一套 React UI 和同一个播放契约，平台差异隐藏在适配器后面。

```text
React UI
  -> useSoundMixer hook
  -> PlayerPort
      -> WebAudioPlayer：Web、Linux、Windows
      -> AndroidNativePlayer：Android
```

UI 不应该知道底层是 Web Audio 还是 Android `MediaPlayer`。

预设属于声音业务数据，不属于播放器实现。UI 读取内置预设分组，调用 `useSoundMixer` 应用预设；`useSoundMixer` 再通过 `PlayerPort` 停止旧混音并播放新混音。

### PlayerPort

前端播放边界定义为：

```ts
export interface PlayerPort {
  play(sound: SoundDefinition, volume: number): Promise<void>;
  pause(soundId: SoundId): Promise<void>;
  setVolume(soundId: SoundId, volume: number): Promise<void>;
  stopAll(): Promise<void>;
  getState(): Promise<PlayerSnapshot>;
  destroy(): void;
}
```

`volume` 是 `0` 到 `1` 的归一化数值。

### 资源策略

第一版为了可靠性采用双份打包：

```text
public/audio/*.ogg
src-tauri/gen/android/app/src/main/res/raw/*.ogg
```

Web、Linux 和 Windows 使用 `public/audio`。

Android 原生播放器使用 Android raw 资源。这样会重复 17 个小音频文件，但能降低 Android 真机播放风险。

### 平台选择

运行时由 `createPlayer()` 选择适配器：

```text
Web browser -> WebAudioPlayer
Linux Tauri -> WebAudioPlayer
Windows Tauri -> WebAudioPlayer
Android Tauri -> AndroidNativePlayer
```

实现可以安装 Tauri OS 插件，也可以使用小型环境检测器。检测失败时必须默认回退到 WebAudioPlayer，保证 Web 预览可用。

### Android 原生播放

第一版 Android 使用 Kotlin `MediaPlayer`：

- 每个 `soundId` 一个播放器。
- `isLooping = true`。
- 每个播放器独立音量。
- 可暂停并释放单个声音。
- 可停止并释放全部声音。

Kotlin 层命名围绕原生播放器概念，例如 `NativeAudioPlayer`。未来可以把内部实现从 `MediaPlayer` 换成 Media3/ExoPlayer，而不改变前端契约。

第一版 Android 不实现前台服务。接口设计不能阻碍未来服务化播放器。

## UI 设计

第一版 UI 保持简单：

- 应用标题。
- 统一播放/停止按钮。
- 预设分组区域。
- 每个预设显示名称和简短描述。
- 17 个声音卡片组成响应式网格。
- 每张卡片显示声音名称。
- 播放中状态要清晰可见。
- 每张卡片有音量滑杆。

UI 必须移除 Tauri 初始模板演示内容。

## 状态规则

- 所有声音初始为停止。
- 每个声音默认音量为 `0.5`，默认预设中的声音使用预设音量初始化。
- 点击停止状态的声音，调用 `play(sound, volume)`。
- 点击播放状态的声音，调用 `pause(soundId)`。
- 移动音量滑杆时更新本地 UI 状态，并调用 `setVolume(soundId, volume)`。
- 点击统一播放/停止按钮时：
  - 如果当前有声音播放，调用 `stopAll()`，并把全部声音标记为停止。
  - 如果当前没有声音播放，播放当前预设或上次混音。
- 点击预设时，先调用 `stopAll()` 清理旧混音，再按预设中的声音和音量调用 `play(sound, volume)`。
- 手动播放、暂停或调音量后，UI 状态必须继续和 `PlayerPort` 调用保持一致。
- 适配器错误要以简短状态消息展示给用户。

## 内置预设

第一版只提供内置预设，不提供用户新增、删除、重命名或排序。预设按场景分组，例如：

- 入睡：偏稳定、低刺激的雨声、风声或篝火组合。
- 专注：偏轻背景的图书馆、办公室、键盘、打字机、时钟或雨声组合。
- 自然：偏环境氛围的森林、风、雷雨、伞下雨声、水面、雪地或风车组合。

每个预设由 `soundId` 和 `volume` 列表组成。预设音量仍使用 `0` 到 `1` 的归一化值。

## 启动脚本

`package.json` 需要提供清晰的平台脚本：

- `dev:web`：启动 Web 开发服务。
- `dev:linux`：启动当前 Linux 桌面 Tauri 开发模式。
- `dev:windows`：在 Windows 环境启动 Tauri 开发模式。
- `dev:android`：启动 Android Tauri 开发模式。
- `build:web`：构建 Web 静态产物。
- `build:linux`：在 Linux 环境构建 Tauri 桌面产物。
- `build:windows`：在 Windows 环境构建 Tauri 桌面产物。
- `build:android`：构建 Android 产物。

跨平台桌面脚本底层都可以复用 Tauri CLI；实际生成 Linux 或 Windows 产物取决于运行脚本的宿主环境和已安装工具链。

## 环境说明

当前本地环境有 Java。写入本设计时，shell 中没有可用的 `adb`，`ANDROID_HOME` 和 `ANDROID_SDK_ROOT` 也未设置。可以规划和尝试初始化 Android 目标，但 Android 构建或设备验证可能需要用户配置 Android SDK 工具链。

## 风险

- Tauri Android 目标生成可能要求把应用标识改成合法 Android 包名。
- `tauri android init` 后要立即检查生成路径。
- Web/Linux/Windows 的 OGG 支持需要手动播放确认。如果某个目标 WebView 无法可靠播放 OGG，再在同一 sound catalog 结构中增加 MP3 fallback。
- Android 后台播放已明确排除，所以第一版移动端播放可能在应用切后台或被系统杀掉时停止。
