# B站听视频设计

## 目标

在现有“声音 / 听书”之外新增“听视频”模式。第一版支持用户粘贴 B 站视频或番剧链接，在应用内通过 B 站官方外链播放器播放，满足临时听视频声音的使用场景。

## 第一版范围

第一版包含：

- 支持粘贴 `bilibili.com`、`www.bilibili.com`、`m.bilibili.com` 和 `b23.tv` 链接。
- 支持解析普通视频 `BV` 号链接。
- 支持解析普通视频 `av` 号链接。
- 支持解析番剧或影视 `ep` 链接。
- 支持用户直接粘贴 `BV`、`av` 或 `ep` 标识。
- 使用 `https://player.bilibili.com/player.html` 官方外链播放器嵌入播放。
- 播放器区域保持可见，允许用户直接使用 B 站播放器自身的播放、暂停、音量、清晰度和跳转能力。
- 点击“载入视频”后通过官方播放器参数尝试自动播放；是否真正自动出声由浏览器、WebView 和 B 站播放器策略决定。
- 链接输入区提供“粘贴”按钮，读取系统剪贴板文本并填入输入框；读取失败时允许用户手动粘贴。
- 显示当前解析出的 B 站标识，方便确认链接是否识别正确。

第一版不包含：

- 不抓取 B 站真实音视频流地址。
- 不下载、缓存、转码或离线保存视频和音频。
- 不把 B 站视频转为本地音频源。
- 不隐藏官方播放器后只播放音频。
- 不绕过 B 站登录、会员、地区、版权、广告或其它播放限制。
- 不做播放列表、收藏、历史记录或账号体系。
- 不做非 B 站平台。

## 架构

新增 `videoListening` 功能域：

```text
B 站链接输入
  -> parseBilibiliVideoInput
  -> buildBilibiliPlayerUrl
  -> iframe 官方播放器
```

解析器只做字符串解析，不请求网络，不调用 B 站非公开接口。解析成功后输出明确的引用类型：

```ts
type BilibiliVideoReference =
  | { kind: "bvid"; value: string }
  | { kind: "aid"; value: string }
  | { kind: "ep"; value: string };
```

播放器 URL 只拼接官方外链播放器支持的参数：

- `bvid` 用于 BV 号。
- `aid` 用于 av 号。
- `episodeId` 用于番剧或影视 ep 号。
- `autoplay=1`，在用户点击载入后尝试自动播放。

## 合规边界

本功能只作为 B 站官方播放器的嵌入入口。应用不拥有、复制、下载或重新分发 B 站内容，不绕过 B 站播放器本身的限制。

如果 B 站官方播放器拒绝某个视频、需要登录、地区不可用、会员不可用或版权不可用，应用只展示播放器自身状态，不尝试降级到抓流或第三方解析。

## UI 设计

听视频模式包含：

- 左侧控制区：模式标题、链接输入、载入按钮、当前视频状态。
- 右侧播放区：官方播放器 iframe 和当前引用摘要。

界面不加入长篇说明文字，只保留必要按钮、输入状态和错误提示。输入框支持粘贴完整链接或短标识；用户可以点“粘贴”从剪贴板填入链接，也可以手动输入。用户点击“载入视频”后更新播放器并尝试自动播放。

## 错误处理

- 空输入显示“请输入 B 站视频链接”。
- 无法识别的输入显示“暂时只支持 B 站 BV、av 和 ep 链接”。
- 非 B 站域名链接显示同样的不支持提示。
- 当前环境不能读取剪贴板或读取失败时，显示明确错误并保留手动输入能力。
- iframe 加载失败不做自定义抓流兜底，只保留官方播放器可见状态。

## 验收标准

- 可以从 `https://www.bilibili.com/video/BV...` 解析出 `bvid` 并生成官方播放器 URL。
- 可以从 `https://www.bilibili.com/video/av...` 解析出 `aid` 并生成官方播放器 URL。
- 可以从 `https://www.bilibili.com/bangumi/play/ep...` 解析出 `episodeId` 并生成官方播放器 URL。
- 生成的官方播放器 URL 使用 `autoplay=1`。
- 粘贴按钮可以把剪贴板文本填入视频链接输入框。
- 不能识别非 B 站链接。
- 顶层应用显示“声音 / 听书 / 听视频”三个模式。
- 切换到听视频不会停止声音调音台或听书。
- 必须通过：

```bash
rtk pnpm run check
```
