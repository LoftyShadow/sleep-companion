# 桌面窗口栏美化设计

## 背景

当前 Windows 和 Linux 桌面端使用系统原生标题栏，窗口控制区和应用本身的睡眠陪伴视觉风格不统一。用户希望最小化、最大化和关闭三个控制按钮更像应用内控件，而不是系统默认样式。

## 目标

- Windows 和 Linux 桌面端隐藏系统原生窗口装饰。
- 在应用顶部提供统一的自绘窗口栏。
- 窗口栏包含应用名称、可拖拽区域、最小化、最大化或还原、关闭三个按钮。
- 窗口栏不展示平台名称，避免把运行平台当作常驻 UI 信息。
- Web 和 Android 不展示这组桌面窗口按钮。
- 按钮视觉与现有玻璃质感、绿色主色和柔和阴影保持一致。
- 桌面端内容滚动条使用浮层指示样式，只在滚动时短暂显示，不占用页面布局宽度。

## 非目标

- 不改变主功能区的信息架构。
- 不新增托盘、菜单栏或多窗口能力。
- 不改变 Android 原生系统导航栏。
- 不引入新的图标库依赖。

## 方案

新增 `AppTitleBar` 组件，作为应用最外层 shell 的桌面窗口栏。组件在运行时判断是否处于 Tauri 桌面环境：

- 非 Tauri 环境：返回 `null`。
- Android 或 iOS：返回 `null`。
- Windows、Linux、macOS：显示自绘窗口栏。

窗口控制使用 Tauri v2 `@tauri-apps/api/window`：

- `minimize()` 处理最小化。
- `toggleMaximize()` 处理最大化和还原。
- `close()` 处理关闭。
- `startDragging()` 处理拖拽窗口。
- `isMaximized()` 用于更新最大化按钮的可访问名称和状态。

`tauri.conf.json` 中关闭桌面窗口 `decorations`，由前端自绘控制区负责窗口操作。

桌面端页面滚动由标题栏下方的内容容器承载，原生滚动条隐藏。滚动发生时，应用在窗口最右侧显示一个不参与布局的浮层滚动指示条，停止滚动后自动淡出。

## 可访问性

- 三个控制按钮使用明确的 `aria-label`。
- 图标为 CSS 绘制，装饰元素设置 `aria-hidden`。
- 最大化后按钮文案切换为“还原窗口”。

## 风险

- Linux 不同窗口管理器对无装饰窗口阴影和拖拽行为支持不完全一致。
- Tauri 权限需要显式允许 `minimize`、`toggleMaximize`、`close` 和 `startDragging`，否则按钮会被运行时拦截。
