# 前端我的登录入口设计

## 背景

后端账户系统基础骨架已经建立，当前数据库和 entity 已经包含账户相关表，但注册、登录、刷新 token 和退出登录接口尚未实现。本轮先补前端入口，在现有应用模式切换中新增“我的”tab，并在该 tab 内放置邮箱密码登录能力。

前一份后端账户基础设计中的“不实现前端登录 UI”只约束后端基础阶段。本设计面向新的前端登录入口阶段。

## 目标

- 在现有 `AppModeSwitcher` 中新增“我的”tab。
- 新增 `AccountView`，暂时只提供邮箱密码登录。
- 新增前端登录请求适配层，后续可以直接接入后端登录接口。
- 登录成功后在当前页面内展示已登录状态。
- 登录失败时展示后端 envelope 中的中文错误信息。
- 保持播放、听书和听视频的状态不因进入“我的”tab 被重置。

## 非目标

- 本轮不实现后端登录接口。
- 本轮不实现注册、忘记密码、邮箱验证、刷新 token、退出登录和多设备会话管理。
- 本轮不持久化 access token 或 refresh token。
- 本轮不接入平台安全存储。
- 本轮不生成 OpenAPI TypeScript client。

## 前端接口契约

前端登录适配层暂定调用：

```text
POST /api/auth/login
```

请求体：

```json
{
  "email": "user@example.com",
  "password": "secret123"
}
```

成功响应继续使用后端统一 envelope：

```json
{
  "code": "ok",
  "message": "ok",
  "data": {
    "accessToken": "access-token",
    "accessTokenExpiresInSeconds": 900,
    "refreshToken": "refresh-token",
    "user": {
      "id": "739182738912312320",
      "email": "user@example.com",
      "displayName": "梦伴用户"
    }
  },
  "requestId": "req_..."
}
```

错误响应沿用后端账户基础设计中的 envelope：

```json
{
  "code": "auth.invalid_credentials",
  "message": "邮箱或密码错误",
  "data": null,
  "requestId": "req_...",
  "details": {}
}
```

前端业务判断优先使用 `code`，用户可见错误文案优先使用 `message`。`requestId` 保留在错误对象中，后续可以接入前端错误日志。

## API 地址

默认后端地址为：

```text
http://127.0.0.1:3817
```

前端支持通过 Vite 环境变量覆盖：

```text
VITE_BACKEND_BASE_URL
```

本轮不改 Vite dev server proxy。这样 Web 开发、Tauri 桌面和后续云端后端地址都通过同一个适配层解析。

## 组件边界

```text
Page / Route：AppWorkspace 负责选择当前 tab，并把登录 handler 注入 AccountView。
Feature Component：AccountView 负责登录表单、提交状态、错误状态和已登录展示。
API Adapter：authApi.ts 负责后端地址解析、请求发送、envelope 解析和错误封装。
Style File：AccountView.css 只承载账号页样式，不把业务样式继续堆到全局 CSS。
```

## 状态边界

- `AccountView` 内维护邮箱、密码、提交状态、错误信息和当前登录结果。
- 登录结果只保存在 React 内存状态中。
- 不在 `localStorage`、`sessionStorage`、IndexedDB 或 Tauri 安全存储中保存 token。
- 后续实现 refresh token、退出登录和会话恢复时，再新增专门的 auth session store。

## 交互约束

- 邮箱提交前会去掉首尾空白。
- 空邮箱直接在前端拦截。
- 密码最小长度沿用后端第一版约定：6 位。
- 提交中禁用输入和按钮，避免重复提交。
- 登录失败不暴露邮箱是否存在，直接显示后端统一错误文案。

## 风险

- 后端登录接口尚未实现，真实点击登录会收到网络错误或接口不存在错误。
- 本轮定义的 `POST /api/auth/login` 需要在后续后端实现时保持一致；如果后端最终改路径，需要同步更新本设计和 `authApi.ts`。
- token 当前只存在内存中，刷新页面会丢失登录状态，这是本轮刻意保留的边界。
