# 后端登录接口设计

## 背景

前端已经新增“我的”tab，并约定通过 `POST /api/auth/login` 执行邮箱密码登录。后端当前只具备账户基础表、配置、健康检查和 migration，尚未提供认证业务接口。

## 目标

- 实现 `POST /api/auth/login`。
- 使用 `app_users` 和 `password_credentials` 校验邮箱密码。
- 使用 `Argon2id` 校验 `password_credentials.password_hash`。
- 登录成功后签发短期 access JWT。
- 登录成功后生成高熵 opaque refresh token，并只保存 `refresh_sessions.token_hash`。
- 登录失败时返回统一错误 envelope，不暴露邮箱是否存在。
- 登录接口接入组合限流，覆盖 `IP`、`邮箱`、`IP + 邮箱` 三类键。
- 同步 OpenAPI schema。

## 非目标

- 本轮不实现注册接口。
- 本轮不实现 refresh token 轮换接口。
- 本轮不实现退出登录和设备会话管理。
- 本轮不实现邮箱验证和忘记密码。
- 本轮不创建开发环境默认用户。

## 接口契约

```text
POST /api/auth/login
```

请求体：

```json
{
  "email": "user@example.com",
  "password": "secret123"
}
```

成功响应：

```json
{
  "code": "ok",
  "message": "ok",
  "data": {
    "accessToken": "access-token",
    "accessTokenExpiresInSeconds": 900,
    "refreshToken": "refresh-token",
    "user": {
      "id": "739182738912312320",
      "email": "user@example.com",
      "displayName": "梦伴用户"
    }
  },
  "requestId": "req_..."
}
```

失败响应：

```json
{
  "code": "auth.invalid_credentials",
  "message": "邮箱或密码错误",
  "data": null,
  "requestId": "req_...",
  "details": {}
}
```

限流命中：

```json
{
  "code": "auth.rate_limited",
  "message": "登录尝试过多，请稍后再试",
  "data": null,
  "requestId": "req_...",
  "details": {}
}
```

## 登录流程

1. 读取并裁剪邮箱，密码保持原值。
2. 如果邮箱为空或密码长度小于配置中的 `auth.password_min_length`，返回 `auth.invalid_credentials`。
3. 根据请求来源生成限流键：
   - `ip`
   - `email`
   - `ip_email`
4. 检查任一限流键是否仍在 `blocked_until` 内。
5. 根据邮箱查询未软删除用户。
6. 根据用户 ID 查询未软删除密码凭证。
7. 使用 `Argon2id` 校验密码哈希。
8. 校验失败时增加三个限流键的失败次数，达到阈值后写入 `blocked_until`。
9. 校验成功时生成 access JWT、refresh token 和 refresh session。
10. 返回统一成功 envelope。

## Token 设计

access JWT 使用 `HS256`，密钥来自：

```toml
[auth]
jwt_secret = "..."
```

JWT claims：

```json
{
  "sub": "739182738912312320",
  "email": "user@example.com",
  "iat": 1780000000,
  "exp": 1780000900
}
```

refresh token 使用 32 字节随机数生成，并通过 URL-safe base64 无 padding 编码返回给客户端。数据库只保存 `SHA-256(refresh_token)`，不保存 token 原文。

## 限流键

限流键不保存明文邮箱或 IP。后端使用 `SHA-256` 计算键哈希，输入包含：

```text
登录限流固定前缀
auth.jwt_secret
key_kind
key_value
```

当前来源 IP 的解析顺序：

1. `x-forwarded-for` 的第一个非空值。
2. `x-real-ip`。
3. `unknown`。

后续部署到固定反向代理后，可以再收紧可信代理来源。

## 错误码

```text
auth.invalid_credentials
auth.rate_limited
auth.token_issue
database_unavailable
```

所有错误响应都必须携带当前请求的 `requestId`。

## 本地使用限制

本轮没有注册接口，因此本地数据库中需要已经存在 `app_users` 和 `password_credentials` 记录才能登录成功。后续可以通过注册接口或开发种子命令补齐用户创建流程。
