# 代码质量与运行边界优化设计

## 背景

本次优化来自对当前主分支代码的只读审查。工作区没有本地未提交改动，审查重点集中在后端认证边界、前端播放链路、自定义音频持久化和前端容器结构。

当前代码已经具备可用的基础能力，但存在几类需要收敛的问题：

- 登录失败限流使用查询后插入或更新的流程，在并发请求下可能触发唯一约束冲突或丢失计数。
- 后端 CORS 使用全量放开策略，不适合作为生产默认边界。
- 多声音播放按声音串行等待，预设和全局播放会叠加启动延迟，也增加浏览器自动播放限制风险。
- 自定义音频直接写入 IndexedDB，缺少文件大小、批量大小和剩余配额保护。
- `SoundMixerView` 和 `AppWorkspace` 承担的状态协调职责过多，后续扩展搜索、收藏、播放总线或更多模块时容易继续膨胀。

## 目标

- 登录失败计数改为数据库原子 upsert，避免并发插入冲突和计数覆盖。
- CORS 改为配置驱动，本地开发保持宽松，生产环境可以显式设置允许来源。
- 多声音播放并发发起，减少预设和全局播放启动瀑布。
- 自定义音频导入前进行容量校验，并在存储配额不足时给出明确错误。
- 拆出播放模块控制总线和工作区滚动指示器逻辑，降低 `AppWorkspace` 职责复杂度。
- 拆出声音库状态逻辑，降低 `SoundMixerView` 职责复杂度。
- 补充或更新测试，保证优化不会改变现有核心行为。

## 非目标

- 不新增账号刷新 token、登出、邮箱验证或密码重置接口。
- 不改变已有登录、注册接口响应结构。
- 不实现 Android 后台播放、锁屏控制或通知栏控制。
- 不改变音频文件目录、声音目录数据结构或素材命名。
- 不新增新的前端样式框架。
- 不重做界面视觉设计。

## 方案设计

### 登录限流原子更新

当前限流记录有唯一索引：

```text
login_rate_limits(key_kind, key_hash, window_started_at) where deleted_at is null
```

优化后，失败登录记录流程使用数据库原子 upsert：

- 按当前窗口计算 `window_started_at`。
- 每个限流 key 使用一条 `INSERT ... ON CONFLICT ... DO UPDATE`。
- 更新分支使用数据库侧 `attempts + 1`，避免应用层读改写覆盖。
- `blocked_until` 在达到阈值时由同一条 SQL 更新。
- 三个限流 key 保持现有顺序处理，后续如有必要再升级为批量 SQL。

SeaORM 的 ActiveModel upsert 对部分索引冲突条件表达有限，本次使用参数化 SQL，并继续走 `ConnectionTrait`。

### CORS 配置化

新增 `CorsConfig`：

- `permissive`：是否使用宽松 CORS。
- `allowed_origins`：非宽松模式下的来源白名单。

默认配置保留本地开发宽松行为；生产配置关闭宽松模式，具体域名由部署环境通过配置或环境变量覆盖。这样不会破坏现有本地开发和测试，但生产不再被硬编码为全量放开。

### 多声音并发播放

`useSoundMixer` 的 `playSoundIds` 改为并发发起底层 `player.play(...)`：

- 先按声音 ID 去重和过滤不存在的声音。
- 对每个有效声音立即创建播放 promise。
- 使用 `Promise.allSettled` 汇总结果。
- 返回成功播放的声音 ID。
- 如果至少一个声音失败，抛出第一个失败原因，让调用方沿用现有失败清理策略。

这样保留当前“预设失败时清理全部”的行为，同时减少串行等待。

### 自定义音频容量保护

新增导入前校验：

- 单文件大小上限。
- 单次批量总大小上限。
- 使用 `navigator.storage.estimate()` 检查剩余配额。
- 当浏览器或 WebView 不支持估算时，仍使用大小上限兜底。
- 保存时识别 `QuotaExceededError`，给出“存储空间不足”的明确错误。

本次不做音频转码、压缩或云端同步，避免扩大范围。

### 前端结构拆分

组件边界：

```text
AppWorkspace：页面编排、模块挂载、浮窗装配。
useWorkspaceScrollIndicator：滚动位置、滚动条可见状态和隐藏定时器。
usePlaybackControlBus：模块播放状态、播放请求 ID、全局播放切换和模块切换。
SoundMixerView：声音混音页面编排。
useSoundLibraryState：声音库模式、分类、可见声音、预设组和统计数据。
useSoundMixer：播放器状态和播放动作。
```

拆分原则：

- 不改变 JSX 结构和 CSS className。
- 不把只有一次使用且语义很弱的 JSX 片段抽成组件。
- 优先抽状态和派生数据 hook，避免制造目录噪音。
- hook 内部使用稳定 callback 和 primitive dependencies，避免引入新的无意义重渲染。

## 数据和接口兼容性

- 后端接口路径、请求体、响应体不变。
- 数据表结构不变，不需要新增迁移。
- 前端 `PlayerPort` 接口不变。
- 自定义音频存储 schema 不变。
- CORS 新增配置字段，默认配置会提供完整字段，旧环境如果只覆盖局部配置不会失效。

## 验收标准

- 并发登录失败不会因为 `login_rate_limits_key_window_idx` 冲突返回 503。
- 失败登录计数在并发场景下不会丢失增量。
- 本地开发和测试环境仍可通过 CORS 预检。
- 生产配置不再使用硬编码 `CorsLayer::permissive()`。
- 多声音播放对多个有效声音并发调用 `player.play(...)`。
- 预设播放中部分声音失败时仍会进入现有错误清理路径。
- 超过单文件或批量限制的自定义音频不会写入 IndexedDB。
- 配额不足时展示明确错误。
- `AppWorkspace` 和 `SoundMixerView` 的状态协调逻辑拆入 hook 后，现有用户可见行为不变。
- 本地质量门禁通过：

```bash
rtk pnpm run check
```

## 风险

- 参数化 upsert SQL 依赖 PostgreSQL 语法；后端当前数据库就是 PostgreSQL，测试层需要用较小粒度单元测试补足 SQL 拼装逻辑。
- CORS 生产白名单需要部署时明确配置真实域名；如果未配置，浏览器跨域访问会被拒绝。
- `Promise.allSettled` 并发播放会更快触发多个底层播放请求，失败清理必须保持现有语义。
- 存储配额估算在不同浏览器和 Android WebView 上精度不同，大小上限仍是主要保护。
- 结构拆分可能引入 dependency 变化，必须用现有 React 测试覆盖播放控制和工作区集成行为。
